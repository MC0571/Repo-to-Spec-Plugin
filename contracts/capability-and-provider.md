# 能力与 Provider 契约

> 基线：DB-20260928 · 状态：待评审提案 · 类型：约束提案
> 本文承接现有愿景，不表示能力已经实现；变更与采纳规则见文档入口。


## 约束

| ID | 目标约束 | 检验方式 |
| --- | --- | --- |
| P-01 | 必需工作不得以特定第三方增强工具为前提；缺必要产品输入另行报告 | 禁用外部 Provider 的代表性任务 |
| P-02 | 发现、配置、授权、就绪和调用成功必须区分 | 未注册、未授权和服务不可用用例 |
| P-03 | 结果必须包含实际范围、版本、限制、截断和失败语义 | 响应合同及部分结果测试 |
| P-04 | Provider 输出不得直接修改范围、接受设计或宣布交付 | 权限与流程边界检查 |
| P-05 | 安装、全局配置修改与资料外发须有适用授权 | 拒绝授权、无网络及敏感材料用例 |
| P-06 | 增强降级不能掩盖观察不足或降低声明范围 | 同范围原生/增强对照与缺口检查 |
| P-07 | 不得把过时索引或不完整搜索当作当前完整事实 | 版本失配与截断故障注入 |

## 请求合同

输入包括 `operation`、`question`、`scope_revision`、`snapshot`、`parameters`、`allowed_effects`、`data_boundary`、`budget` 和取消条件。具体函数名、JSON 字段和协议编码可以随正式接口评审调整，语义不能在适配层丢失。

## 结果合同

结果包含请求标识、提供者标识与版本、执行状态、实际操作范围、数据、材料引用、观察条件和限制。状态为 `success / partial / unavailable / permission_denied / unsupported / stale / timeout / cancelled / execution_error`。

空结果与失败必须可区分；成功查询不等于成功回答交付问题。原生文本追踪与专业符号分析可以采用相同结果外壳，但必须保留不同的完整性声明。

## 扩展准入

每个新 Provider 需要说明具体改进的交付问题、数据与执行边界、预期收益、可用版本、失败行为及回归场景。没有它时能否达成交付，要针对声明目标与可用输入验证，不能仅检查适配器列表中存在一个 native 名称。
