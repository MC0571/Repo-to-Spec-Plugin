# 契约目录

> 基线：DB-20260928 · 状态：待评审提案 · 类型：约束提案
> 本文承接现有愿景，不表示能力已经实现；变更与采纳规则见文档入口。


## 契约的角色

本目录把目标设计中需要保持的行为写成可检查约束。所有条款当前均为**待评审提案**，不是对仓库现有运行能力的描述。接受状态由设计评审变更；检测器和运行验证是否实现必须单独记录。

| 契约 | 内容 |
| --- | --- |
| [交付与独立交接](delivery-and-handoff.md) | 范围、设计完备、自包含和导出 |
| [工作流与状态](workflow-and-state.md) | 恢复、修订、失效、问题与发布 |
| [能力与 Provider](capability-and-provider.md) | 能力就绪、权限、失败、降级和数据边界 |
| [质量与发布门](quality-gates.md) | 结构/语义/消费检查、阻塞、回归与完成判断 |

本文中的“必须”是拟接受的目标合同，不意味着已经存在强制执行代码。格式检查、程序断言、语义审阅和隔离实验是不同检查方式；不能把一条自然语言 MUST 称为操作系统级安全保证。

## 变更与追踪

每个条款有稳定 ID。更改既有语义需要说明原因、影响对象、相关验收、兼容风险和回归；仅移动文件不改变 ID。条款的具体实现进入未来工作包，不能在本目录伪装成已完成。

能力与验收的关联在 [设计登记表](../docs/planning/design-baseline.json) 维护。`scripts/check_design.py` 检查登记表完整性与引用，不执行这些产品合同的全部验证。当前限制见 [验证策略](../docs/planning/VALIDATION-STRATEGY.md)。
