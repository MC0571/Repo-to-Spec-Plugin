# 交付与独立交接契约

## 约束

| ID | 目标约束 | 必须留有的判断依据 |
| --- | --- | --- |
| D-01 | 每次交付必须声明目标产品版本、范围、环境和显式排除；改变范围必须有决定记录 | 范围修订及授权；不能把输入缺失转为排除 |
| D-02 | 范围内产品、适用体验和必要逻辑技术设计必须共同完成 | 交付义务、设计元素与语义审阅 |
| D-03 | 恢复事实、独立设计与用户授权改动必须在内部可区分 | 材料依据、设计理由或用户决定 |
| D-04 | 实现自由必须明确允许差异及不可改变的结果；重要未决不得归入自由 | 自由项和对应验收 |
| D-05 | 最终实施包必须仅依靠公开设计与声明依赖可被消费，不要求回查参考仓库 | 隔离消费结果；包内引用检查 |
| D-06 | 导出必须采用允许清单并验证解析后路径；不能递归复制内部工作区 | 公开产物清单及越界失败用例 |
| D-07 | 选择性吸收必须处置所选能力的传递依赖 | 纳入、边界契约或批准的改动/排除记录 |
| D-08 | 发布不得忽略必要资产的使用条件，也不得以隔离为由删除必要通知 | 资产说明与适用审阅；不作自动授权保证 |

## 推荐记录形状

范围记录：`scope_id`、`revision`、`target_version`、`mode`、`selected_capabilities`、`supported_environments`、`exclusions`、`dependency_dispositions`。内部关联参考快照与用户决定，公开范围不提供源码补课入口。

自由项：`freedom_id`、`design_element_ids`、`choice_dimension`、`allowed_variations`、`preserved_constraints`、`acceptance_refs`。仅写一个空的“implementation details”字段不满足合同。

独立设计依据不要求对应源码行，但必须关联被满足的已确认规则与约束。对目标产品本身的未知行为不能借独立设计记录绕过 D-03。

## 失败语义

D-01 至 D-07 的违反会阻止最终导出。D-08 涉及适用条件与判断主体；条件未解决且资产对交付必要时阻塞，不能用免责声明继续分发。已形成的草案可以保存，但不能标为最终或完整套件。

## 验证范围

路径、引用和字段适合自动验证；关键设计是否完成、是否忠实、是否仍隐含来源依赖，需要语义和独立消费检查。扫描通过不能自动满足 D-02 或 D-05。
