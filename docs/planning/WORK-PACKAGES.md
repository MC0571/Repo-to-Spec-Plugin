## 每个 Issue 必须写清的内容

标题表达要闭合的交付问题；正文列出 Cxx/Mx/适用 Axx 与契约 ID、范围内外、先决输入、需要变更的权威文档、目标产出、验证方法、失败反例和完成证据。公开格式或重大架构改变需关联 ADR；不适用某字段时说明理由。

工作包可以拆分为更小 PR，但不得把验收和失败处理无限推后。先提交协议或接口的 PR，要明确实现尚不存在；后续实现 PR 要提供实际可运行命令，不引用一个未创建的 CLI。

## PR 组织建议

本设计包可以作为一次独立的设计基线 PR，保留所有提案状态，逐项接受。后续运行选型、任务状态、单类设计流程、导出与验证分别通过聚焦 PR 进入主分支。不要把整套未来实现一次性塞入本次文档修改。

检查命令只使用仓库已定义入口；新产品命令在实际实现后写入 AGENTS。严禁在 README 写出当前不可执行的安装或生成指令，制造已经交付的印象。
