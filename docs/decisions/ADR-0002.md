# ADR-0002：按交付切片交错理解与设计

> 基线：DB-20260928 · 状态：已采纳 · 类型：架构决策
> 本文承接现有愿景，不表示能力已经实现；变更与采纳规则见文档入口。


## 状态

2026-09-28 由维护者采纳；依据与适用范围见 [M0 采纳记录](../reviews/M0-ADOPTION.md)。后续替代时保留历史并指向新 ADR。

## 背景

完整愿景要求减少下游前置工作，且现有 VISION §7.3 不要求穷尽全仓后才产出设计。

## 决策

围绕产品能力/工作流推进产品、体验和技术的联合切片，设计缺口驱动定向调查，持续整合共享规则。

## 替代方案与取舍

先建全量证据库再写规格会形成重型前置；一次性长 Prompt 难以恢复和发现跨能力冲突。

## 后果与验证

需要权威共享模型、切片依赖和重开机制；不能将局部闭合当全局完成。

## 重新评估条件

如果切片划分导致频繁冲突，依据实际依赖合并或调整切片，而非加更多调度层。
