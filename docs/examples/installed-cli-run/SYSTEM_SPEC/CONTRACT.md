# 命令、反馈和运行设计

## C1 公共入口

目标命令名为 `skill-precheck`，发行包须提供此可执行入口；安装方式由目标产品决定。

```sh
skill-precheck ./my-skill ./another-pack
```

无子命令，无交互确认，无配置文件，无自动修复或输出文件参数。每个位置参数都当作目录，因此以 `-` 开头的值也不是选项；没有 `--help` 选项。无参数时向 stdout 打印用途、用法、检查范围和退出码说明，然后退出 2，不进行扫描。shell 中含空格的路径由调用者引用。

| 退出码 | 意义 | 调用方处理 |
| --- | --- | --- |
| 0 | 扫描完成且 ERROR=0，可能有 WARN 或零个 Skill | 可应用目标产品自己的后续发布策略 |
| 1 | 规则失败或运行失败；有正常结果行表示扫描完成，否则未完成 | 展示 stdout/stderr，修复内容或环境后重跑，不当作预检查通过 |
| 2 | 无参数 | 展示用法，补充目录参数后重跑 |
| 130 | 用户 SIGINT 中断 | 不使用部分输出作为完整结果，可重跑 |

其他进程被杀死/宿主超时/信号退出也必须被调用方视为未完成。输出不是稳定 JSON API；自动化门禁以退出码为准，不依赖英文错误消息的正则提取。计数供人/Agent 阅读；要机器化扩展应另设版本化接口，版本 1.0 不含它。

## C2 输出体验

不显示进度百分比，无提示输入。逐个输出 Skill 概览，然后扫描总数，接着全部 WARN，再全部 ERROR，最后结果。组内保持 RULES 的遍历/发现顺序。全部正常报告写 stdout，成功与规则失败的 stderr 为空。终端纯文本、无需颜色和鼠标；无 GUI，因此焦点、导航、视觉布局与响应式断点不适用。

概览使用 `  skill: {目录名} {行数} 行 {字节数} 字节`；空格对齐不构成契约。其余正常报告格式为：

```text
共扫描 {M} 个 .md，其中 {S} 个 SKILL.md
WARN  [{code}] {path}: {message}
ERROR [{code}] {path}: {message}
结果: {E} errors, {W} warnings
```

只有存在相应诊断时输出对应行。前后空行可变。路径应能定位调用输入中的文件，允许相对或绝对形式但一次运行保持统一，不要求转成符号链接目标路径。诊断不承诺行号。

| code | 级别 | message 所需内容 |
| --- | --- | --- |
| input | ERROR | 目录不存在或不是目录，并给出参数路径 |
| encoding | ERROR | 非法 UTF-8 |
| frontmatter | ERROR | 分隔/解析失败统一为“frontmatter 缺失或不可解析”；字段失败分别为“缺少非空 name”或“缺少非空 description” |
| name-style | WARN | 原始 name 及“不符合小写连字符风格” |
| name-dir | WARN | 原始 name、目录末级名及“不一致” |
| broken-ref | ERROR | 捕获的目标字符串及“不存在” |

对操作失败，stderr 输出 `FATAL [runtime] {阶段或路径}: {原因}`，退出 1，不再输出“结果”行；之前的概览允许保留但不构成完整报告。不把权限错误假装成 broken-ref 或空目录。中断时尽力向 stderr 输出 `CANCELLED: 检查中断，结果不完整`，退出 130，不输出正常结果。依赖缺失同样采用 runtime 消息，不启动安装。stderr 无需 traceback。

## C3 生命周期和职责

状态只有：启动 → 参数与运行条件检查 → 按根扫描 → 汇总 → 完成（0/1）；任意操作异常转未完成（1），SIGINT 转取消（130）。无参数直接用法退出。输入目录错误属于规则诊断，可继续；无法读取已发现文件、读取中消失、目录枚举异常属于运行错误，立即终止。不把不完整扫描与内容不合格混为一谈。

逻辑职责：入口协调参数与退出码；枚举器输出排序候选；读取器生成一次 UTF-8 归一化文本；规则层产生诊断；报告层保留遍历顺序、累计计数并呈现。每份文本仅读取一次，同一文本同时用于引用、元数据和大小统计；严禁加载或执行被检 Skill 的代码。解析器由实现者选择，但不得执行被检包的代码，且须满足 RULES 的解析语义。

所有状态只存内存，无数据库、缓存、锁文件、报告文件或包内标记。不得修改、格式化或修复输入，不执行包内命令，不创建编译/发布目录。文件系统可能更新访问时间，不将其视作工具写内容。宿主可捕获输出到包外日志，日志权限、保存与删除由宿主负责。

## C4 稳定性、并发与资源

同一稳定目录树、参数顺序与支持环境下，多次运行须产生相同计数、诊断顺序和退出码。不同进程独立，无共享可变诊断列表；未来若提供进程内接口，每次调用也须清空状态。并发只读运行不互相加锁或写文件。

不提供全树快照，也不承诺识别所有检查期间修改。调用方须从启动到退出保持内容、目录项和相关引用目标稳定；发布前再发生修改应重跑。若修改导致可观测 I/O 失败，返回未完成；未触发异常的并发修改无法保证检出，因此退出 0 不是某个发布版本的原子证明。

无额外大小阈值、自动忽略或超时。实现可逐文件处理，避免全包内容驻内存；至少需容纳一个文件的文本、YAML 解析、单根排序路径和累积诊断。宿主可施加内存/时限，达到限额只能视为未完成，不允许跳过文件后报告成功。不得读取 FIFO 等无限流；支持的是普通本地文件。符号链接跟随和 `..` 存在性检查遵守进程已有权限，调用者若需要隔离应提供受限文件系统。
