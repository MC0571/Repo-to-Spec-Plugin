# 行为规则

## R1 输入和遍历

CLI 接受至少一个目录路径，按参数先后分别扫描。相对路径基于调用时工作目录，不展开 `~` 或通配符（shell 已展开的参数除外）。不存在或不是目录的参数产生一个 `[input]` ERROR，然后继续其他输入。参数可重复或包含父子重叠目录；不跨输入去重，计数和诊断相应重复。

每个根递归枚举所有后缀精确为 `.md` 的项，包含隐藏目录和隐藏文件；无 `.gitignore`、node_modules 或其他排除规则。按路径字符串的 Unicode 码点顺序处理。后缀 `.MD` 不扫描。根本身是目录符号链接时允许扫描；递归途中不进入目录符号链接；文件符号链接会读取目标，但相对引用以链接所在路径的父目录为基准。匹配到名为 `x.md` 的目录、设备、FIFO 等非普通文件（允许指向普通文件的链接）使运行未完成，见 CONTRACT。目录不可枚举不得当作空目录成功。

每个候选在读取前增加 Markdown 计数；按严格 UTF-8 解码，将 CRLF 和单独 CR 都转换为 LF。UTF-8 BOM 不剥除。无效 UTF-8 产生一个 `[encoding]` ERROR，跳过该文件其余处理。可解码的文件先做引用检查，然后仅当末级文件名精确等于 `SKILL.md` 时增加 Skill 计数、检查元数据并输出概览。因此小写 `skill.md` 只检查引用；编码损坏的 `SKILL.md` 不计入 Skill 数；元数据无效的 `SKILL.md` 仍计入 Skill 数并输出概览。

## R2 frontmatter 与命名

对归一化后的文本执行以下步骤，不使用完整 Markdown 解析器：

1. 必须从第一个字符开始具有 `---` 前缀；在索引 3 起寻找第一个 `\n---`。找不到任一分隔条件，产生一个 `[frontmatter]` ERROR，并结束元数据检查。
2. 取开头三个字符之后、结束分隔符的 LF 之前的字符串作为 YAML。分隔符无须独占整行：`---name: good` 可开始，`---suffix` 可结束。正文和结束分隔符剩余内容不参与 YAML 解析。
3. 使用等价于 PyYAML 6.0.3 `safe_load` 的语义，禁止任意对象构造。解析异常或结果不是映射，产生一个 `[frontmatter]` ERROR，并结束元数据检查。空 YAML、标量、序列都不是合法映射。重复键采用加载器的末值；支持安全加载器的锚点/别名/合并，未知或不安全 tag 解析失败。布尔、数值、日期等隐式类型不自动转字符串。
4. 依次检查 `name` 和 `description`，各自必须是字符串且按 Python Unicode `str.strip()` 去掉首尾空白后非空；每个失败字段各产生一个 `[frontmatter]` ERROR。多余字段允许，正文可以为空，无字段长度限制。
5. 若 name 有效，使用未 trim 的原始值做两项独立警告：Python `re.match` 模式 `^[a-z0-9][a-z0-9-]*$` 不匹配时 `[name-style]` WARN；与文件所在目录末级名不逐字符相等时 `[name-dir]` WARN。大小写敏感，不修正值。此正则允许末尾连字符，且 `$` 允许在最后一个 LF 之前匹配；这些不应额外升级为 ERROR。

示例：name 为未加引号的 `123`、`true`、`null` 都无效；`"123"` 有效；`" good "` 有效但有命名风格和目录不一致警告。description 为多行非空字符串有效。BOM 在开头导致缺失 frontmatter。

## R3 引用识别、跳过与存在性

扫描整份可解码文本，包括 frontmatter、代码块、行内代码和注释；不判断是否为实际渲染链接。使用以下 Python Unicode 正则语义，按第一种匹配的文本顺序、再按第二种匹配的文本顺序处理，均只取捕获组 1：

```text
Markdown: \]\(([^)#\s]+?)(?:#[^)\s]*)?\)
裸路径:   (?<![\w/(])((?:references|assets)/[\w\-./]+\.[a-zA-Z0-9]+)
```

对每个捕获值做 Unicode strip，同一 Markdown 文件内按得到的目标字符串去重，两种识别器共享该集合。忽略以小写 `http://`、`https://`、`mailto:` 或 `/` 开头的目标。其余均视为文件系统路径：拼接到当前 Markdown 路径的父目录，按操作系统的路径解析语义检查存在性。不存在产生一个 `[broken-ref]` ERROR，携带 Markdown 路径和捕获目标。文件或目录存在即通过，不检查类型、内容或可读性；指向不存在目标的符号链接视为不存在。系统无法确认存在性（如权限错误）使运行未完成。

没有根目录包含性限制：`..` 可解析到根外；不做 URL 解码，不剥离查询参数，不联网，不检查 fragment 指向的标题。`a.md` 与 `./a.md` 是两个去重键，即使最终解析到同一文件也分别检查。

| 输入片段 | 精确行为 |
| --- | --- |
| `[x](a.md#one) [y](a.md#two)` | 只检查一次 `a.md`，不验证锚点 |
| `![x](pic.png)` | 检查 `pic.png` |
| `](x)` | 也识别 `x`，无须左侧有配对方括号 |
| `[x](#one)` | 不识别 |
| `[x](a.md "title")`、`[x](a b.md)` | Markdown 识别器不识别 |
| `[x][id]` 与 `[id]: missing.md` | 不识别引用式链接 |
| `[x](a%20b.md)`、`[x](a.md?q=1)` | 检查字面文件名，不解码/去查询参数 |
| `[x](ftp://host/a)`、`[x](HTTPS://host/a)` | 当作相对路径检查，不属于跳过前缀 |
| `` `references/a.md` ``、`assets/img.png` | 裸路径识别，即便在代码内 |
| `foo/references/a.md`、`(references/a.md)` | 裸路径不识别：前字符分别为 `/`、`(` |
| `references/a.md#x` | 裸路径识别 `references/a.md` |
| `[x](references/a.md "title")` | Markdown 识别失败，裸路径亦因前字符 `(` 而不识别 |
| `[x](references/a.md#x)` | 两种规则总体只检查一次该目标 |

正则而非完整 Markdown 文法是权威；嵌套括号等复杂内容可能匹配部分目标，不能宣称覆盖全部链接。裸路径只覆盖 `references/` 与 `assets/`，不覆盖任意裸 `scripts/`、`resources/` 路径。

## R4 汇总

每个可解码的 `SKILL.md` 输出其所在目录末级名、归一化文本的 LF 数加 1、归一化文本重新编码为 UTF-8 的字节数。这是文本统计，不是磁盘字节数、token 数或 YAML 正文统计。空文本行数为 1；末尾有 LF 仍多计一行；CRLF 文件的统计字节数比磁盘大小少。

所有根共享本次调用的计数和诊断列表。ERROR 数是诊断条数，不是失败文件数。WARN 不影响通过。未完成的运行不能输出正常最终结果；详见 CONTRACT。
