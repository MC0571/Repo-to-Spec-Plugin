# Skill 触发评测与发布前门禁

**状态：草案。** 当前没有目标产品的本地触发选择器契约、发布前调用接口或已确认的通过阈值。本文定义能力边界、结果语义和待闭合依赖；在阻塞项解决前，评测结果只能作为诊断，不能声称已形成可用发布门禁。

## 目标与范围

Skill 包维护者在现有发布流程提交一个本地候选包后，使用本地评测用例核对候选 Skill 是否会在应触发的用户请求上被选中、是否会在不适用请求上被抑制，以及是否会把请求路由给正确的相邻 Skill。评测结果由现有发布流程消费。

本能力包括：本地用例集、触发选择器的隔离评测、逐例计分、运行报告，以及发布前放行/阻止结果。它不包括内容蒸馏、Skill 编译或更新、Skill 实际任务执行质量、候选包实际发布或新的发布产品界面。

**参与者**：Skill 维护者维护本地用例与预期结果；现有发布流程准备待评测候选包并消费评测状态；本地评测执行器按目标运行环境的 Skill 选择机制返回所选 Skill 标识或 `none`。

**实现自由**：实现语言、框架、操作系统、命令语法、用例序列化格式、内部模块和报告版式。实现不得改变下述评测结果、隔离、数据边界与发布门禁语义，也不得要求目标产品改用来源仓库的目录、脚本或 JSON 格式。

## 术语和数据

- **候选快照**：现有发布流程准备、将要发布的本地 Skill 包内容；评测以内容摘要绑定具体快照。
- **评测套件**：维护者在本地测试目录保存的一组稳定用例及预期选择。它属于测试资产，不自动成为已发布 Skill 包格式的一部分。
- **目标 Skill**：本次评测关注的 Skill 标识。
- **竞争 Skill 清单**：实际选择环境中可与目标竞争的其他 Skill 及目标选择机制所需的元数据。清单须与发布后实际触发上下文相符。
- **评测执行器**：调用目标产品当前 Skill 选择路径的本地适配能力。独立的任意模型判断不能替代该选择路径。

本草案暂按一次请求最多选择一个 Skill 或 `none` 建模；目标产品若允许一次激活多个 Skill，结果契约和逐例预期须按实际运行语义修订。

每个用例至少包含稳定用例标识、用户请求文本、场景类别、预期所选 Skill 标识（或 `none`）及维护者侧的预期理由。运行策略包含重复次数和通过标准。评测执行器不得获得预期选择或维护者理由。

用例类别应区分：目标应触发、与目标无关的请求、应由竞争 Skill 处理的请求、边界请求。类别和预期结果是两个维度：边界请求可预期触发目标、选择竞争 Skill 或选择 `none`；竞争 Skill 用例必须指定准确的预期 Skill 标识。

## 规范规则

### R-CASE：用例覆盖和版本

1. 每个候选目标 Skill 都有本地评测套件；套件标识、修订版本及每条用例标识在一次评测中保持稳定。
2. 套件应覆盖目标正例、无关负例和边界请求。存在会与目标争用同类请求的 Skill 时，至少包含一条明确预期路由到该竞争 Skill 的混淆用例。
3. 本草案建议的初始覆盖为 3–5 条目标正例、2–3 条无关负例、1–3 条边界用例；若实际选择环境有相邻竞争 Skill，再至少加入一条 Skill 混淆用例。目标产品尚未确认这些数量及无竞争 Skill 时的策略；最终数量属于发布策略待决项，未确认时不得把该建议伪装成已验证的正式门槛。
4. 用例预期须在运行前固定。看到结果后修改预期，必须留下理由并生成新的套件修订；新修订仍须对保留用例评测。未使用的用例和失败结果不得从本次报告分母中删除。
5. 保留集不得参与当前候选 Skill 的调优；交给评测执行器的输入不能暴露预期类别、预期 Skill、理由或通过标准。保留集管理方与目标产品对用例可见性的授权范围尚未给定。

### R-EVAL：触发选择评测

1. 发布前，现有发布流程把候选快照和对应本地套件提交给评测能力。候选快照在评测和发布之间保持不变；若内容摘要发生变化，原评测结果失效，须对新快照重跑。
2. 执行器必须使用发布后真实使用的 Skill 选择路径、候选 Skill 元数据和竞争 Skill 清单。只凭 Skill 名称列表或与目标运行机制不同的独立分类器所得结果不能证明触发行为符合发布环境。
3. 每条用例的每次重复都在独立、无跨用例记忆的上下文中执行。执行器只返回选中的 Skill 标识或 `none`。解释可选且不参与判分；不得要求或保存隐藏推理文本。
4. 本能力只评测选择结果，不执行已选 Skill 的任务，也不给评测上下文执行用户工具、修改候选包、写入发布目标或调用未授权外部服务的权限。套件、候选包与报告由本地评测能力保存在本地；选择器仅可通过目标产品已有授权调用远端模型，不能隐式回退到未授权服务。
5. 无效用例、选择器不可用、运行错误、超时、取消、缺少或重复结果均使本轮为未完成。部分结果不得按完整运行计分或放行发布。

### R-REPORT：结果

每次评测生成本地报告，至少关联候选包内容摘要、套件修订、执行器及选择环境版本（可得时）、计划和完成运行数、逐例预期与实际选择、各类别计数、失败/未完成原因及采用的通过策略。报告可以省略用户请求全文，以稳定用例标识回查本地套件。

状态只有：

- `passed`：所有计划运行均有且仅有一个结果，候选摘要仍匹配，套件有效，并满足测试开始前固定的全部通过标准。
- `failed`：评测完整，但至少一个用例或类别未达到预设标准。
- `incomplete`：输入或运行无效、执行失败、超时、取消、结果缺失/重复，或候选摘要不匹配。

报告必须将每次结果作为分母的一部分；总分或平均值不得掩盖无关负例误触发、竞争 Skill 错路由或未运行的用例。通过标准须在执行前固定，并分别说明目标正例、无关负例、竞争 Skill、边界类别和重复运行如何影响通过状态。本草案建议无关负例零容错；其他类别的统一数值阈值未定，目标产品须确认最终策略。在策略未定时只能输出诊断状态，不得产生 `passed`。

### R-PUBLISH：现有发布流程的门禁

现有发布流程在任何发布副作用之前评测同一候选快照。只有 `passed` 可继续既有发布动作；`failed` 与 `incomplete` 均阻止发布并向维护者显示状态、未通过用例标识和可操作原因。修复候选包或套件后重新运行；未完成结果不得被视为通过。

门禁只决定是否允许现有流程继续。发布、回滚、目标环境部署和版本更新的语义由目标产品既有流程负责，超出本能力范围。

## 外部依赖

| 依赖 | 提供者与契约 | 失败语义 |
| --- | --- | --- |
| 候选快照 | 现有 Skill 包流程提供本地可读、内容稳定的待发布目录及内容摘要；摘要必须指向实际发布的同一内容。 | 不存在、不可读或变化时返回 `incomplete`，不继续发布。 |
| 本地 Skill 选择器 | 目标运行环境提供一个本地可调用入口，使用实际的候选元数据、竞争 Skill 清单和发布后相同选择机制，为单条请求返回 Skill 标识或 `none`。 | 不可调用、版本不匹配或无法使用实际选择上下文时返回 `incomplete`。目标环境尚未提供此契约，是阻塞项。 |
| 评测套件 | 目标产品本地测试目录中的维护者资产；由目标维护者提供已固定的预期和通过策略。 | 缺失、无效、覆盖不足或策略未定时不得放行。 |
| 发布决策 | 目标产品现有发布流程作为消费者，只接受与候选摘要一致的 `passed` 结果。 | 评测失败、未完成或结果不匹配时，不执行发布动作。目标流程的实际扩展点尚未核实。 |

## 验收场景

1. **应触发**：给定完整候选快照和正例，隔离执行器按固定重复策略运行；每条结果选中预期目标，报告含全部用例与运行。
2. **无关请求**：给定预期为 `none` 的负例，执行器选中目标则报告对应类别失败；不得由其他正例成绩抵消。
3. **相邻 Skill**：给定预期由竞争 Skill 处理的用例，执行器必须选中该确切竞争 Skill；选择目标或其他 Skill 均记失败。
4. **边界请求**：每条边界用例显式给出预期选择；报告依该预期计分，不因“边界”标签自动算作负例。
5. **隔离与盲测**：评测输入包含请求和目标运行所需的候选 Skill 上下文，不包含预期结果、类别、理由或阈值；每次重复使用独立上下文。
6. **漏测与错路由**：删去一个计划运行或让相邻 Skill 用例选中错误 Skill，结果不得显示通过。此场景能发现“部分结果仍有满分指标”的错误。
7. **运行故障**：选择器超时、返回非法 Skill 标识、被取消或报告缺失时，状态为 `incomplete`，现有发布流程拒绝继续。
8. **候选变更**：评测后改变 Skill 元数据或包文件，内容摘要不再匹配时，旧报告不能为新内容放行；必须重跑。
9. **门禁顺序**：失败或未完成时，不发生任何发布动作；匹配候选摘要的完整通过报告才允许现有发布流程继续。

## 阻塞项

1. **实际触发执行器未确认**：没有目标产品材料证明本地环境可调用与发布后一致的 Skill 选择器，也没有确认授权的模型/宿主调用入口。未解决前无法验证真实触发行为。
2. **发布前集成点未确认**：未提供目标包暂存、候选摘要和现有发布流程消费门禁结果的接口证据。未解决前不能确认评测结果绑定实际发布物。
3. **通过策略未确认**：目标产品的套件数量、重复次数、保留集管理方和各类别通过阈值未定。参考仓库的建议数与诱饵零容错只作为候选输入，不代表目标产品已批准。
4. **运行上下文未确认**：目标 Skill 包的结构、同一触发环境中的竞争 Skill 清单、选择器是否单选及模型/执行器版本管理未提供。未解决前只能规定概念契约，不能声明对真实目标环境可用。
