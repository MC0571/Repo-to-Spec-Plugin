## 执行者的原始判断与实际证据

执行者把选择器调用、逐例判分、候选包快照和发布消费拆成不同责任，排除来源产品的蒸馏/编译/更新。它没有把来源 Python 脚本、JSON 格式或调查机平台提升为目标必装依赖。来源 `run_trigger_evals.py` 实际提供 split/prepare/score，**不调用真实 Skill 选择器**；只给 Skill 名称的准备包也不足以证明发布环境的触发行为。目标选择器契约、发布前集成点、通过策略和实际竞争上下文缺失，于是原始套件标为**草案/阻塞**，没有声称门禁可用。

执行者在隔离临时目录造合成用例，实际运行来源 runner 的 split、prepare、score；首次探针误以为随机训练集必含指定用例，失败属于探针断言，改用 `--set all` 后继续。提交 4/5 个计划结果且错选一个兄弟 Skill 时，来源仍报告 F1 `1.000`，退出 `0`。我另用独立的 3/4 结果探针复核：`score` 退出 `0`，输出 `TP 1 / FP 0 / FN 0 / TN 2`、F1 `1.000`，逐例表却写“未中兄弟(wrong-sibling)”。这些测试只验证来源 runner 在该输入上的计分行为，没有运行目标产品选择器或发布集成。

## 两种审查与修订

**对照来源的作者核查**：阅读来源 runner、相关方法与工作记录，并独立复核上述漏测/错路由探针。原始草案将完整性核对、兄弟 Skill 的确切选择、同路径选择器和快照绑定作为有理由的目标推导，而没有声称来源脚本已具备这些能力。该核查由本轮作者完成，不算独立来源审查。

**脱离来源的独立消费**：另一名未参与编写、只读原始正式草案的接收者，确认主要目标环境依赖被暴露，但指出六处实施歧义：诊断状态缺失、逐次错误与整轮阈值冲突、保留集可见性、旧报告失效条件、选择后能否停止执行、多 Skill 包聚合。作者据此形成单独的[评审修订草案](method-depth-trial/reviewed/SYSTEM_SPEC/README.md)，保留原稿不变。接收者复查又指出无关负例阈值和 `diagnostic/incomplete` 优先级两处措辞冲突；作者修订后，第三次来源隔离复核未发现剩余实质内部矛盾。该复核仅说明修订草案更可读、更一致，**不证明来源忠实性、宿主能力或目标产品实施就绪**。

## 反馈到插件方法

- [行为与异常恢复](../../plugins/repo-to-spec/skills/repo-to-spec/references/behavior.md)：批量/评测先核对来源的完成、抽样与去重语义，再从输入求计划集合并与实际结果逐项对齐；本次要求全量唯一的门禁中，缺失、重复和未知结果使运行未完成；兄弟项须核对确切预期，不能只看聚合分数。
- [工具指南](../../plugins/repo-to-spec/skills/repo-to-spec/references/tools.md)：给出计划标识与重复次数对照实际报告的操作和反例核对。
- [数据接口与约束](../../plugins/repo-to-spec/skills/repo-to-spec/references/contracts.md)：决定后续动作的报告要绑定全部语义输入，并明确保留集可见性和多目标聚合。
- [选择性吸收](../../plugins/repo-to-spec/skills/repo-to-spec/references/absorption.md)：目标环境提供的局部执行路径须真的能在约定边界停止，避免无意执行排除的后续动作。
- [规格审查](../../plugins/repo-to-spec/skills/repo-to-spec/references/review.md)：接收者要核对状态集合、逐次错误和整轮阈值、验收是否暗定策略、报告失效和保留集泄露。
