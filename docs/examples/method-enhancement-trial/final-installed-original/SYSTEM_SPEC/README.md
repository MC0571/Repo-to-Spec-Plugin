# score 原始报告规格

本套件定义从本地 suite JSON 与外部逐例选择结果 JSONL 生成 Markdown 原始报告的能力。兼容基线为 `874eb414e6414dd6d399222a7e3925206dfdb585`。面向维护者：给出目标入口的 TP/FP/FN/TN、precision/recall/F1、兄弟混淆率和按输入顺序列出的配对行，供人阅读分析。

本交付是可独立实施的最终规格；不包含目标程序实现，也不声称目标环境已经集成。语言、框架、操作系统、命令启动器和内部模块组织均可选择。必须保持的是本文档定义的输入接受语义、判定、文本和完成/失败行为。无需访问任何参考仓库。

## 阅读与权威

1. [输入与运行契约](CONTRACT.md)：入口、文件提供者、宽松输入域、执行顺序及失败恢复。
2. [判分与报告](SCORING.md)：唯一的判分、计数及报告模板定义。
3. [值兼容规则](VALUE_SEMANTICS.md)：比较、键身份、非字符串转文本和浮点格式。
4. [验收](ACCEPTANCE.md)：黄金夹具及失败/恢复场景。

上述正文规范性规则优先；`fixtures/` 是具体输入及预期报告，补充验证正文，不另设规则。报告文本按 Unicode 字符精确兼容；夹具采用 UTF-8 无 BOM、LF 换行。宿主原生换行转换可使物理字节为 CRLF，验收时仅允许将 CRLF 归一为 LF；不允许改写空白、标点、字段值或转义。支持 UTF-8 输出时，stdout 是报告再追加一个换行。错误诊断的堆栈、程序名、路径呈现不要求逐字兼容。

## 范围与依赖闭合

| 项目 | 处理方式与所有者 | 必要契约及验收 |
|---|---|---|
| suite | 目标环境的维护者或本地文件提供者外供 | 调用前提供稳定、可读的 UTF-8 文件；字段按 CONTRACT，不要求生成过程或完整 suite Schema。缺失/不可读导致失败，修复后重跑。 |
| 逐例结果 | 外部结果生产者外供 | 调用前交付稳定 JSONL；每条是一次观察，不要求完整覆盖或 run 唯一；缺失选择值有兼容默认。未知 case、重复和空文件均按正文处理。 |
| 判分、解析兼容、报告排版 | 纳入本能力 | 本套件完整定义；可替换解析器，但不能用严格 Schema 缩小已接受域。 |
| 文件系统与终端 | 目标运行环境提供 | 以调用者权限读取输入、创建报告父目录和覆盖输出；相对路径以工作目录解析；可捕获 stdout、stderr、退出状态。成功、不可写、写后输出失败按 CONTRACT 验收。 |
| 报告消费 | 维护者 | 阅读原始计数；报告完成不表示选择质量达到标准，也不表示所有计划执行已完成。 |

外供契约已经闭合；具体目标集成尚未实施。无需真实选择器、模型服务、技能安装目录、网络、身份服务、数据库或消息队列。suite 中 prompt、notes、runs、split 配置不被用于判分。split/prepare 的算法与实现、盲测管理、发布准入、通过阈值、统计非劣检验、输出质量评测均明确排除。报告结尾保留的统计提示只是兼容文本，不引入这些依赖。

只有命令行与文本文件交互，无图形 UI、页面、视觉设计或用户账号体系。一次调用同步完成；维护者拥有输入和报告，程序没有持久任务状态、缓存或历史评估库。
