# 值、相等与文本兼容

以下是语言无关的兼容层定义，不要求实现使用 Python。JSON 标准表示法不是本报告的非字符串文本表示法；例如 null 输出 `None`，对象输出单引号键，而不是 JSON 双引号键。

## V1 值与相等

保留 null、布尔、整数、binary64 浮点、Unicode 字符串、有序数组、保留键插入顺序的对象的区别。

普通相等 E(a,b)：

- null 只等于 null。
- 字符串按精确码点序列比较，区分大小写，不做 Unicode 规范化；不与任何非字符串相等。
- 布尔参与数值比较，false=0，true=1。整数之间按精确值比较；整数与浮点按浮点的实际二进制数值和精确整数比较，不把大整数先舍入。`1=1.0=true`，`0=-0.0=false`。正/负无穷分别只等于同号无穷；NaN 普通相等恒为假，包括与自身比较。
- 数组只与数组比较；长度相同且对应元素满足下面的成员相等 M 才相等。
- 对象只与对象比较；键集合相同、对应值满足 M 即相等；对象键排列顺序不影响相等，但影响文本表示。
- 其他跨类型配对不相等。

成员相等 M 除普通 E 之外，还对同一个被解码为共享 NaN 字面量的值返回真。所有文件中的 JSON 扩展 `NaN` 使用同一个规范 NaN 标记。这保留容器内元素身份比较的可见效果：标量 NaN 与 NaN 不相等，而 `[NaN]` 与 `[NaN]` 相等，`{"a":NaN}` 与同结构对象也相等。数值溢出产生的正/负无穷按正常无穷规则处理。任意其他相同对象身份不带来不同于递归 E 的结果（JSON 无循环引用）。

索引键仅可为 null、布尔、整数、浮点、字符串；数组/对象不能作键。键查找及覆盖使用 E，另将所有 `NaN` 字面量键看成同一键。因此 suite 的 case_id 为 true、结果 case_id 为 1.0 会匹配；suite 内 1 和 true 的两条 case 后者覆盖前者。字符串 `"1"` 不匹配数值 1。

解析转义应将合法 UTF-16 代理对组合为一个 Unicode 码点；未配对代理码点保留为值，输出时按 V2 或编码失败规则处理。

## V2 直接显示 D 与容器表示 R

`D(v)` 用于标题、case_id、run、expected、selected 和未中兄弟括号内值。

| 类型 | D(v) |
|---|---|
| 字符串 | 原始字符串本身，不加引号，不转义 |
| null | `None` |
| 布尔 | `True` 或 `False` |
| 整数 | 十进制精确整数，无加号/前导零；JSON 整数 `-0` 显示 `0` |
| 浮点 | V3 的 F(v) |
| 数组 | `[` + 各元素 R 以 `, ` 连接 + `]`；空数组 `[]` |
| 对象 | `{` + 各键值对 `R(键): R(值)` 以 `, ` 连接 + `}`；按键首次插入顺序；空对象 `{}` |

`R(v)` 在非字符串类型上与 D 相同并递归，在字符串上是带引号的表示：

1. 默认选 ASCII 单引号包围。字符串含单引号但不含双引号时改用双引号包围；两种引号都含时仍选单引号。
2. 将反斜杠转为 `\\`，将选用的包围引号在内容中加一个反斜杠。另一种引号原样保留。
3. TAB、LF、CR 分别转为 `\t`、`\n`、`\r`。其余不可打印码点：≤FF 用小写十六进制 `\xhh`；≤FFFF 用 `\uhhhh`；更大用 `\Uhhhhhhhh`（大写 U、小写十六进制、固定位宽）。不改用 `\b`、`\f` 或 JSON 的转义斜线。
4. 可打印码点原样输出，包括汉字、emoji。可打印定义为 Unicode 15.0 General_Category 不属于 C（控制、格式、代理、私用、未分配）或 Z（分隔符），另 U+0020 普通空格可打印；NBSP U+00A0 不可打印。这一定义仅影响容器中的带引号字符串；D 的直接字符串不受此过滤。

示例（代码块中的反斜杠是实际输出字符）：

```text
D(null)                  → None
D(false)                 → False
D("a|b")                 → a|b
D([true,null,"字"])      → [True, None, '字']
D({"a": "it's"})         → {'a': "it's"}
D({"a": "a\"b"})        → {'a': 'a"b'}
D({"a": "both'\""})     → {'a': 'both\'"'}
D(["\n\t\u0001\u00a0"]) → ['\n\t\x01\xa0']
```

直接字符串中的 LF 是真正换行；上述数组中的 LF 是反斜杠加字母 n。不得用统一 JSON 序列化代替 D/R，也不得统一把所有值先强制为字符串再比较。

## V3 浮点文本 F 与统计格式

F 使用 binary64 最短、可往返还原同一浮点值的十进制有效数字（最近值，中点取偶）；这是数值解析后的表示，不保留原 JSON 的词法写法。负零为 `-0.0`，正零为 `0.0`；NaN 为 `nan`，正/负无穷为 `inf`/`-inf`。

非零有限数：取最短有效数字串及十进制指数 k（最高位对应的十次幂）。若 -4≤k<16，采用普通十进制形式，整数形的浮点末尾加 `.0`；否则采用科学计数法，首位后有其他有效数字才插入小数点，指数标记小写 `e`，指数总带 `+` 或 `-`，绝对值至少两位。不加多余尾零。负数前置 `-`。

| 输入词法 | F |
|---|---|
| `1.0` / `1e0` | `1.0` |
| `-0.0` | `-0.0` |
| `1e-4` | `0.0001` |
| `1e-5` | `1e-05` |
| `1e15` | `1000000000000000.0` |
| `1e16` | `1e+16` |
| `1e20` | `1e+20` |
| `1e400` | `inf` |
| `1.2345678901234567` | `1.2345678901234567` |

JSON 整数 `10000000000000000` 则仍显示该整数，不变成 `1e+16`。实现可采用等价最短浮点转换算法，无需依赖特定解释器。统计比率不使用 F，而用 SCORING 的三位定点格式；例如精确中点 0.0625 显示 `0.062`，0.1875 显示 `0.188`。资源不足、过深嵌套或超出运行环境可解析整数长度可作为运行失败；不能用此作为拒绝正常非字符串值或数值相等语义的理由。
