# 输入、执行与恢复

## C1 入口和路径

提供等价入口：`<launcher> score <suite.json> --results <results.jsonl> --out <report.md>`。三个路径均必需，选项可与位置参数交错；`--results=路径`、`--out=路径` 可用，重复同名选项取最后值。无隐式配置、环境变量评分设置或默认输入/输出路径。路径含空格由调用者按其 shell 传参；不自行展开 `~`。启动器和帮助文字可按目标语言包装；缺参数、未知参数应给 stderr 用法诊断、退出 2，且不读取或改写报告。`score --help` 显示这三个参数，退出 0、不生成报告。接受无歧义长选项缩写，例如 `--res`；不要求提供其他子命令。

相对路径基于调用进程工作目录，绝对路径直接使用。按宿主文件系统规则跟随符号链接，不检查输入与输出是否同一路径；同一路径时输入已读入后会被报告覆盖。调用者须避免在需要保留输入时使用这种路径。程序不执行输入中的代码或指令，也不对字段内容做 Markdown 安全转义。

## C2 解码与实际输入域

输入按 UTF-8 严格解码，UTF-8 BOM 不剥离，含 BOM 的 JSON 在解析时失败。JSON 允许标准值及扩展字面量 `NaN`、`Infinity`、`-Infinity`；小数/指数数采用 IEEE 754 binary64，溢出可为无穷大；整数保留整数类型与精确值，不先转浮点。JSON 对象保留插入顺序，重复键取末值，但键的位置保留首次出现位置。拒绝语法错误、未转义控制字符和尾部非空白内容。解析空白是 JSON 空白（空格、TAB、CR、LF）。数值、比较和文本细节见 VALUE_SEMANTICS。

suite 整文件解析为一个值。正常根对象仅需要 `target` 和 `trigger_cases`；不校验 schema_version、suite_id、prompt、notes、runs、split_seed、train_ratio、output_cases，也不读取这些值。额外字段忽略，不能因其缺失或值不合 Schema 而拒绝 score。

| 字段 | 常规供给 | 兼容接受及读取时机 |
|---|---|---|
| suite.target | 目标技能字符串 | 必须存在，可为任何 JSON 值，用于比较和标题；不强制 slug、非空或字符串。 |
| suite.trigger_cases | case 对象数组 | 必须存在；按顺序建立索引。空数组、空对象、空字符串均可形成空索引。非空对象迭代的是其字符串键，非空字符串迭代字符，随后因不能按 `case_id` 取字段而失败；null/数字/布尔不可迭代而失败。 |
| case.case_id | 字符串 | 每个被遍历 case 必须是对象并含此键；只接受可作键的 null/布尔/数值/字符串，数组和对象失败。按 VALUE_SEMANTICS 的键相等规则匹配；同键后一个 case 整体替换前一个，无合并。 |
| case.expected | 四种常规标签 | 只在结果命中此 case 时必需，可为任意 JSON 值；三种特殊字符串以外均进入兄弟分支。未命中的 case 缺此键不会失败。 |
| case.sibling_target | 兄弟技能字符串 | 只在兄弟分支读取；缺失默认 null，可为任何 JSON 值。 |
| result.case_id | case 标识 | 每条非空行解析成对象后必须有该字段；可作键的类型同上。未知标识跳过，但仍计入 runs。 |
| result.selected_skill | 技能字符串或字符串 `none` | 仅命中 case 后读取；缺失默认字符串 `none`，显式 null 不默认。任何 JSON 值均可比较和呈现。 |
| result.run | 次数标记，常规为整数 | 仅用于输出，缺失默认整数 1，显式 null、布尔、容器、负数等保留原值；不用于排序、去重、筛选或完整性检查。 |

results 整文件读入后按逻辑行切分。分隔符：LF、CR、CRLF（视作一个）、VT U+000B、FF U+000C、U+001C–U+001E、NEL U+0085、U+2028、U+2029。尾随分隔符不额外制造数据行。若行仅含 Unicode 空白则忽略；判空集合为 U+0009–000D、U+001C–0020、U+0085、U+00A0、U+1680、U+2000–200A、U+2028–2029、U+202F、U+205F、U+3000。非空行以未裁剪文本独立解析一个 JSON 值，故 NBSP 包围 JSON 不作为 JSON 语法空白接受。JSON 字符串中直接出现 U+2028 也会先被断行；用六字符 `\u2028` 转义则不会。所有非空行先解析完成，再处理任一结果。

结果行不要求唯一、不要求按 case 或 run 排序、不校验选择是否属于已安装技能、不给缺失计划运行补行或补 FN。`runs` 是解析成功的非空行数，包括未知 case；不是 suite 声称的执行次数。

## C3 顺序、状态与失败

必须保持以下可观察先后关系，可用任意内部机制实现：

1. 读/解析 suite；取 target；遍历全部 trigger_cases 建索引。
2. 读 results，切行并解析全部非空行。
3. 顺序处理结果，遇到无效行对象/缺键/不可用键等即失败；按 SCORING 累计并构建所有报告文本。
4. 递归创建输出父目录（已有目录可用）。以覆盖方式写 UTF-8 报告，再向 stdout 输出相同报告加一个换行。
5. 完成退出 0。任意分数均可退出 0，空集也可退出 0，stderr 正常为空。

| 失败阶段 | 外部结果与副作用 | 恢复 |
|---|---|---|
| 参数错误 | stderr 用法诊断、退出 2；不产生报告 | 更正参数重跑 |
| 输入读取、解码、JSON 解析、结构访问、匹配或报告构建失败 | stderr 诊断、退出 1；不输出正常报告，不创建输出父目录，不改已有报告 | 维护者修复文件/权限/数据后整次重跑；旧报告不是本轮产物 |
| 创建目录/打开输出失败 | stderr 诊断、退出 1；无完整 stdout；可能已创建部分父目录，打开失败通常保留旧文件 | 修复路径/权限后重跑 |
| 输出写入/编码失败或写时中断 | 不得声称成功；普通运行错误退出 1；报告可能缺失、为空或部分写入，已有文件可能已截断 | 检查并重跑覆盖；无自动回滚或事务承诺 |
| 写报告成功后 stdout 失败 | 命令失败，文件可能已经完整；stdout 可能部分输出 | 检查文件和输出通道，必要时重跑 |

诊断应能区分读取/解析/结构/写出错误并指向相关输入或字段；不要求复制特定语言堆栈或底层异常字符串。系统信号中断的退出码遵循宿主约定；不设计取消 API。不能承诺断电持久性或原子写入。输入中未配对代理码点可以被 JSON 解码，但若进入报告直接字符串导致 UTF-8 编码失败，属于输出失败；若经容器表示被转成 ASCII 转义则可输出。

同样输入重复调用重新计算并覆盖同一输出，不累加、不创建版本。程序无锁、去重和并发调度；调用者应串行写同一输出路径。同路径并发无完整报告保证；不同路径独立。没有计划任务状态、自动重试或资源配额产品承诺。逻辑职责可划分为输入解析与兼容值层、索引与计数层、纯文本格式层、文件与终端输出层；这些是可替换内部组织，执行顺序和副作用边界不可改变。
