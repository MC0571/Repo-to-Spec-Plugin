# 目标集成与准入未决

## 从发布请求到决定

既有发布流程冻结待发布包和候选环境 → 管理员冻结 suite、切分、运行计划和预注册策略 → 真实选择器逐次盲测 → 归集检查完整性 → 计算原始指标与匹配 → 发布方核实报告对当前发布仍有效 → 按已批准策略做包级决定 → 原发布流程消费决定。

目前能实施中间的计划、归集、评分、报告模块；前端真实选择调用和末端准入策略未给出。`没有可用准入结论` 与 `质量不合格` 不同。此规格不发出发布许可，也不推定目标流程已会阻止发布。目标方必须在接入前明确无结论的处理，才能闭合端到端门禁。

## 依赖处理

| 依赖 | 处理与提供者 | 契约、失败与恢复 | 验收与状态 |
| --- | --- | --- | --- |
| suite、固定切分、原始评分 | 纳入本能力 | S-1 至 S-6、R-1/R-2；无效或未完整不给最终结果 | A-1 至 A-8，已闭合 |
| 既有 Skill 包与竞争环境 | 目标包管理/发布系统提供 | 稳定快照、实际候选 ID/顺序/内容及解析结果；读取失败或漂移使运行不可用，新建运行 | A-9、U-2，未核实 |
| 真实选择器 | 目标宿主提供、适配器衔接 | 只做选择、独立上下文、单选/none；返回关联 ID 与错误；调用失败不等于 none | A-10、U-1，未核实 |
| 结果归集、报告、隔离职责 | 纳入逻辑设计；目标提供运行身份与存储权限 | R-2 至 R-6，只有完整提交结果可消费；中断整轮重跑 | A-7/A-11/A-12，核心闭合，权限集成未核实 |
| 通过阈值与统计策略 | 目标产品/风险责任方提供 | 每指标、类别、次数的判定与缺类处理，预注册；不得看过验证结果再挑阈值 | A-13、U-3，关键未决 |
| 包级准入与发布消费 | 目标发布责任方提供 | 目标覆盖清单、聚合、失败/无结论、人工复核、覆盖权限与发布动作关联 | A-14、U-4，关键未决 |

来源的蒸馏、编译、Registry、写锁和发布器不作为传递依赖：所需输入是目标包的稳定可见快照，不强制目标重建来源产物链。若目标包与真实选择器加载的内容不同，须由 U-2 给出可验证的转换或实际加载快照，不能只因都是目录就认定等价。

## U-1 真实选择器契约

需要目标宿主负责人提供：实际入口（命令/API/回调及版本）、输入与响应样本、候选发现与展示机制、单选或多选语义、选择完成后能否停止且不执行任务、模型/提示/工具/权限配置、隔离方式、身份权限、错误/超时/取消、预算与重试约束。

影响：不能证明“真实触发”，不能定适配器传输，也不能承诺零任务副作用。若宿主原生多选或无法截断执行，必须决定如何调整目标范围/评价语义，不能擅自压成单选或启动执行。核心评分仍可用人工构造向量验收，标 synthetic。

## U-2 候选集合与目标覆盖

需要包负责人提供：待评目标列表、候选包含哪些本包/外包/路由 Skill、真实顺序、name/description 和其他可见内容、加载版本与资源摘要、slug/别名到结果 ID 的映射、每个 sibling_target 的实际对应、发布包与加载包的关系，以及目标用例集。

影响：竞争环境会改变选择结果；不能只安装当前 target 测出高分。不得默认来源整包或本包就是目标完整候选。多目标可分别建 suite 和报告，但未定覆盖清单前不能宣称“全包已测”。

## U-3 阈值与通过规则

需要产品风险责任方在看保留集结果前明确：使用哪些指标及数值/方向、各类硬失败、兄弟精确匹配是否单独必需、缺类/零分母的政策、重复次数聚合、训练与验证结果用途、是否比较旧版基线、若要求非劣则另给方法/样本量/界值和基线。

影响：matched/mismatched 只描述逐次预期符合性，不推出目标或整轮“通过”。来源方法中诱饵容错为零是其压力测试要求，脚本未执行该门；来源设计中的 F1 0.85、混淆率 10% 是待基线验证的假设，不能移作目标阈值。本套件既不默认全对才通过，也不默认达到某 F1 即通过。

## U-4 发布决定及消费契约

需要发布负责人提供：哪些目标必须测、单项如何聚合到包、指标失败与评测未完成分别如何处理、待人工复核条件、策略审批主体与版本、能否覆盖及审计、报告新鲜度和策略变化后的复用规则、何时冻结/重核发布上下文、发布身份与回执、取消/重复请求/超时结果未知的处理。

影响：即使所有目标报告 completed，也不能自动映射为整包允许发布。缺某目标、报告失效或无策略均无充分依据签发准入；目标现有流程如何阻断/等待/转人工尚未核实。补齐后需将允许/拒绝/待决等最终状态、发布副作用和重试行为写成具体契约，并用 A-14 验证；不能以“由 CI 自行处理”代替。

## U-5 权限与支持环境

需要部署/安全负责人提供：宿主平台支持矩阵、凭证提供方式、评测管理员/调优者/审核者的权限映射、保留集存储与日志隔离、保留与删除周期、运行资源限制。

影响：不阻止平台无关模块实现，但阻止声称目标已符合盲测隔离、运维恢复或特定平台可用。语言与数据库可以选；秘密如何保护不是无条件实现自由。

## 补齐后交付条件

U-1/U-2 用真实宿主单选、none、错误和无任务副作用验证；U-3 以预注册政策明确阈值两侧和类别边界；U-4 用完整、缺失、失效、多目标冲突、发布超时穿透；U-5 验证调优者无法读取保留集。完成后才能将本套件升级为端到端最终规格。当前未决不是要求停止已经闭合的核心实现。
