## 发现、修正与限制

已验证事实：来源校验器把名称与目录不一致作为警告，因此正例退出 `0` 并不能证明标准格式或宿主加载。补查官方 Agent Skills 格式后，套件明确将完整标准验证交给目标发布流程；插件调查方法也要求检查适用外部标准与参考检查器的差异。正式规格定义了本能力的校验语义和边界，不把来源脚本路径作为实现要求。

作者自检：逐项核对范围、依赖、无 UI 的命令反馈、错误状态、只读性、可观察验收与套件内引用；未把本记录的源码位置带进正式套件。独立接收者只读正式套件时指出引用识别、符号链接和重复统计三处不可判定；首轮修订后又指出读取失败的例外与 URL 片段优先级冲突。已据参考材料和正反例补齐 SPEC 与 A9–A12，并将两轮发现反馈到插件的审查指令。该接收者再次仅凭正式套件复查，确认上述阻断已解决、可在声明范围内独立实施和验收；这不是目标实现的运行验证。整包独立审查进一步发现 frontmatter 标记语义被未经确认地收紧；实测后按来源行为修正为 A13。

另以缺失参考路径、没有产品资料的私有 GUI 请求试用入口方法：执行者明确输出“已阻塞”，没有生成或标记最终套件，指出需要参考材料、范围和环境输入。这验证了该输入条件下的失败表达，不证明所有缺材料情形都能被识别。

此样例只覆盖一个无图形界面的局部能力。当前宿主未实际加载新插件；未验证跨宿主加载、所有 Markdown 语法边界、完整 Agent Skills 合规性或其他类型产品的规格生成效果。
