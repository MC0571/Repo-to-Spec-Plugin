## 1. 执行者与控制方式

宿主 Agent 执行语义理解与设计；本地程序处理可重复的状态、格式与检查；用户只处理必要授权、无法从材料解决的输入和产品取舍。一个宿主可承担多个逻辑角色，不因此宣称进行了独立评审或真正的多 Agent 并行。

统一入口负责判断新任务、恢复、更新、只读检查或重审。入口不加载全部专业流程；当前切片需要 CLI、UI、数据或运行调查时再加载相应内容。具体技能组织见 [插件与技能模型](PLUGIN-AND-SKILLS.md)。

## 2. 完整生命周期

| 环节 | 进入条件 | 必须形成的结果 | 不通过时 |
| --- | --- | --- | --- |
| 接入与范围 | 用户给出仓库或相关材料 | 目标版本、范围模式、支持环境、输入与授权清单 | 缺必要输入则说明影响，保留阻塞；不猜测 |
| 产品面发现 | 范围可解释 | 能力、参与者、入口、数据、体验、配置与外部依赖清单 | 不把未知标为不适用；继续定向发现 |
| 交付规划 | 有可开展切片及共享约束 | 切片依赖、目标产物、完成条件、上下文引用 | 优先解决影响多个切片的阻塞 |
| 理解与设计 | 相关材料与必要权限可用 | 产品、体验、逻辑技术设计草案及依据 | 草案保留未知，安排针对性调查 |
| 局部审阅 | 切片已有可消费设计 | 完整性、忠实性、约束与实现自由检查结果 | 退回具体设计缺口，不全量重启 |
| 跨切片整合 | 若干局部结果可用 | 统一术语、状态、数据所有权、依赖、权限与错误语义 | 重开冲突项，不能局部都通过就跳过 |
| 交付候选 | 声明范围内内容形成 | 多格式候选、清单、公开引用、验收资产 | 失败不覆盖已有有效包 |
| 交付门与导出 | 候选具备可检查内容 | 结构、语义、隔离与消费检查通过后的不可变包 | 仍有阻塞则仅输出草案和缺口说明 |
| 更新与反馈 | 参考版本、范围或质量反馈改变 | 影响集合、新修订和重新验证结果 | 无法定位影响时扩大复核，不宣称无需检查 |

上述环节允许往返。先形成一个交付切片并发现设计缺口，再补调查，符合愿景的“边理解边完成设计”；不能把表格误读成必须全仓串行完成的阶段。

## 3. 每个工作项的最小协议

工作项包含：服务的交付结果、范围版本、前置条件、相关材料引用、需要解答的问题、预期设计产物、完成条件、允许副作用、负责角色、依赖项和失败处理。

一次执行必须返回：实际完成的内容、变更的对象与修订、仍有的未知、受影响的共有规则、验证结果及下一步建议。不得只返回“已研究”“无明显问题”或一个没有上下文的长摘要。

交接引用权威状态与变化，不重新手写整套世界状态。新上下文读取切片、当前范围、相关设计与问题；不默认旧聊天记忆可信。

## 4. 调度与资源

优先级由影响决定：阻断多项能力的共享规则、阻止交接的重要未知、风险高而依据薄弱的设计、接近可审阅的切片。仓库文件数、工具数量和记录量不是调度目标。

允许对互不依赖的切片并行理解；共享产品规则、术语、数据模型和最终包清单由指定整合者写入。无法确认冲突安全时串行整合。并行执行需保存所读基线版本，过期写入必须拒绝或重审。

预算耗尽、上下文不足、网络不可用等只能导致暂停、草案或显式调整请求。用户未批准前不能缩小范围。停下时记录可恢复检查点和剩余交付，不伪造最终完成。

## 5. 何时需要用户

可以自主完成：常规检索、受允许的运行观察、恢复已存在规则、在既定约束内完成逻辑设计、整理产物、执行已授权检查。

必须请求必要输入或选择：缺失且影响产品结果的外部状态；有副作用的运行或第三方安装授权；不能从材料消除的关键产品冲突；改变范围或目标产品规则；引入不在既定允许范围内的数据外发。

请求必须给出具体缺口、已尝试方法、影响的交付和可选处置。不能把“请用户解释整个仓库”当作默认工作流程。

## 6. 中断、恢复与更新

恢复先校验范围版本、参考快照、工具可用性及检查点完整性；仅重用仍有效的结果。输入版本变化会使相关依据、设计、覆盖与验收标为待复核。不能只看文件名未改就复用运行观察。

交付后更新产生新包版本，并提供产品语义变化、设计变化和兼容影响。无法确定是否影响已公开契约时保持待复核，不将不确定性归入实现自由。

协议的可检查约束见 [工作状态契约](../../contracts/workflow-and-state.md)。
