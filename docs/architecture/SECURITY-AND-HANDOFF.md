# 安全与独立交接边界

> 基线：DB-20260928 · 状态：已采纳 · 类型：目标设计
> 本文承接现有愿景，不表示能力已经实现；变更与采纳规则见文档入口。


## 1. 边界不是法律结论

本设计承接现有愿景的独立交接原则，不提供任何许可、合同、知识产权或合规保证。工程隔离不能自动获得内容使用或资产再分发权限；必要审查由使用者及有资格的专业人员负责。

重点是输入与输出的技术边界：研究者可以接触参考材料，实施者只接收可独立使用的设计套件。不能要求同一上下文“忘记”源码就宣称实现了隔离。

## 2. 输入不可信

参考仓库、README、注释、测试数据、Issue、生成物和 Provider 结果都视为待分析材料。它们包含的命令或指令不自动获得执行权限，不得覆盖用户意图、宿主安全策略或插件执行契约。

读取仓库、运行构建/测试、启动目标服务、访问网络和安装工具分别评估副作用。代码运行可能写文件、联网或读取凭证，不能因为名为 test 就默认安全。优先使用用户允许的受限环境，不自动修改宿主全局配置。

## 3. 必要执行条件

任务开始记录可读取范围、可写工作区、允许运行的程序与网络边界、敏感数据限制以及工具安装授权。安全检查不套用 reverse-skill 的攻击授权模型，而应服务本产品真实副作用。

权限不足时准确说明阻塞的观察或验证；只读调查仍能推进的部分可以继续，但不足以完成的交付不得被标为完成。

## 4. 导出允许清单

导出器从被审阅的产物清单组装实施包，不递归复制整个工作区。检查包内路径、符号链接解析、嵌套引用、远程资产和文件类型。解析后超出候选根目录的路径必须拒绝；不能只做字符串前缀比较。

禁止通过默认导出夹带：原源码、内部映射、调查与运行日志、宿主绝对路径、凭证、未脱敏数据、要求回查原仓库的链接。公共标准链接或必要运行依赖不等同于源码依赖，但关键目标行为仍要在套件中说清。

有必要保留的归属、许可证或其他通知不能为了“看不出来源”而删除。需要通知、需要专用资产授权或与严格盲交接要求出现冲突时，应明确评审交付模式或替换资产；不得声称技术扫描解决了权利问题。

## 5. 公开投影与追踪

内部记录“哪段材料支持哪个判断”；公开记录“哪个设计要求由哪个验收场景验证”。同一设计元素的公开内容不依赖内部 ID 解释，不附源码路径充当说明。

关键来源隔离测试：将最终包复制到不含参考仓库、不含研究上下文、无研究工具缓存的消费环境，检查所有设计、数据和验收是否仍可用。仅删除 Markdown 超链接不充分，二进制资产、样例数据和归档也需要检查。

## 6. 外部工具与资料外发

Provider 声明其执行位置、网络目的、数据范围与保留行为。默认不得把整个私有仓库发送给一个新 Provider；授权只覆盖明确数据与目的。凭证由宿主管理，不写入可移植插件元数据或提交文件。

工具失败、拒绝授权或数据外发不被允许时，尝试已允许的替代能力；不存在足够替代路径则保留具体阻塞，不伪造观察。

## 7. 限制与验证

静态秘密扫描、路径和引用检查能检测部分边界违规，但不能证明自然语言无泄露、无错误归因或无许可风险。高风险资产和语义独立性需要人工或语义审阅，且应明确方法限制。

安全回归至少覆盖：指令注入样本、路径穿越、越界符号链接、导出中混入内部记录、凭证字段、默认网络外发、失败候选覆盖旧包。对应要求见 [交付契约](../../contracts/delivery-and-handoff.md)。
