# 工作状态、内部依据与增量更新

> 基线：DB-20260928 · 状态：待评审提案 · 类型：目标设计
> 本文承接现有愿景，不表示能力已经实现；变更与采纳规则见文档入口。


## 1. 目标与推荐实现

状态为恢复、纠错和复用服务，不单独形成证据平台。本提案建议用**任务级文件存储、结构化清单及可重建索引**实现初始目标架构；这是可替换的工程选择，不是“永远不能用数据库”的产品原则。

运行技术栈和精确磁盘编码尚未锁定。下列语义应先稳定，再选择最小足够实现；状态结构和插件包目录不混用，不能把用户工作数据写入只读安装包。

## 2. 状态分区

| 分区 | 保存内容 | 访问与持久性 |
| --- | --- | --- |
| 安装包 | 技能、契约、内置检查器、模板 | 通常只读、由插件版本控制 |
| 宿主本地状态 | 能力发现结果、可失效缓存、客户端绑定 | 不含明文凭证；更新或过期时重新探测 |
| 任务工作区 | 输入快照、范围、切片、内部依据、设计、问题与审阅 | 用户私有、可恢复、明确保留与删除策略 |
| 交付暂存区 | 准备导出的公开产物、完整清单与检查结果 | 不得作为已发布交付；失败可丢弃或留作诊断 |
| 已发布套件 | 冻结的公开设计与必要资产 | 不可静默修改；新内容生成新版本 |

目标原则是隔离权限和生命周期，不要求机械创建五套持久化服务。

## 3. 最小权威状态

任务至少记录：任务标识、状态格式版本、插件版本、范围版本、参考快照、交付切片清单、设计元素修订、问题与覆盖义务、审阅结果、已发布包清单。源码摘录、运行日志和外部工具响应按需保存，不每次复制全部输入。

内部依据指明支持什么、在什么版本和条件下成立、有什么限制。对恢复事实可以保存材料位置；对独立设计保存约束和理由；对用户改动保存决定记录。信心描述不能代替依据，也不强制生成没有校准意义的百分数。

## 4. 一致性与并发

权威记录采用单写入责任和修订号检查。写入方提交 `expected_revision`；不匹配则返回冲突，而不是最后写入覆盖。对多个关联文件的修改，先在暂存区写完整记录及清单，再提交一个可验证的检查点指针。不能声称若干独立文件写操作天然具有事务性。

具体实现需在目标平台验证同目录替换、崩溃恢复和文件同步语义。不依赖尚未验证的网络文件系统保证；不满足条件时明确不支持并发写入或更换存储实现。

衍生搜索索引和覆盖汇总可重建；它们不能成为第二个权威设计来源。时间线记录变更与原因，不重复整个任务状态。

## 5. 失效传播

参考快照、产品上下文或范围变化后，从受影响依据沿“支持/依赖/承载/验收”关系传播待复核状态。共享配置、权限、数据所有权、状态机变化需要跨切片传播；不能只使当前编辑文件失效。

缓存键至少考虑材料版本、操作及参数、环境、工具或模型版本和权限范围。无法获取稳定版本或依赖集合时采取保守失效。读取失败、响应截断和过时图索引必须作为限制记录。

输出更新应说明：已复用的部分、重新调查的部分、变化的规范元素、兼容影响与尚未通过的验证。不用“重新生成成功”代替变更解释。

## 6. 发布与可重现

候选包记录完整文件清单、内容摘要、套件格式版本及范围标识；检查通过后才切换有效交付指针。哈希保证字节身份，不保证语义正确或法律授权。

所谓可重现首先指：可以重新取出同一冻结包，并解释其对应的范围、设计和审阅。模型再次运行得到逐字相同结果不是默认承诺；确定性打包、语义等价复核与模型生成稳定性分别测试。

## 7. 数据与权限

秘密不写入通用状态；需要凭证时使用宿主管理的授权上下文。用户资料、运行样本和未脱敏日志不自动发布、同步到公共经验库或发送给新 Provider。导出采取允许清单，内部依据默认排除。

数据清理包含工作区与缓存；已经发布的套件是否需要撤回或替换由版本流程处理。部署到新存储前，应通过恢复、隔离和兼容测试，并记录取代此提案的 ADR。
