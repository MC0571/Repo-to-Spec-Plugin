# 插件、技能与宿主适配

> 基线：DB-20260928 · 状态：待评审提案 · 类型：目标设计
> 本文承接现有愿景，不表示能力已经实现；变更与采纳规则见文档入口。


## 1. 继承现有仓库约定

本提案沿用 `CONTRIBUTING.md` 的插件与技能格式选择，不引入一套竞争入口。核对日期为 2026-09-28：Agent Plugins 页面声明规范 1.0.0，状态为 Working Draft；Agent Skills 页面定义技能格式。规范发布状态不等于任意客户端已经支持，实际宿主必须独立验证。来源见 [参考资料](../REFERENCES.md)。

目标分发包采用根 `plugin.json`、`skills/<name>/SKILL.md` 和按需提供的 `mcp.json`；客户端扩展使用声明的扩展机制。当前设计文件包不包含可安装插件，不能把元数据样例当成可运行能力。

## 2. 包、技能与运行能力

插件负责可安装分发；技能负责向 Agent 提供交付方法；辅助运行能力负责适合自动化的状态和验证。三者不等同于最终系统规格套件。

正式发布包应自包含所需技能和规则。源码仓库作为这些内容的单一来源，构建或打包时纳入发布产物；不要求最终使用者另找某个 canonical Git 仓库再绕过包边界读取核心流程。

客户端适配只能改变加载、调用、权限桥接和结果呈现，不能复制并改写另一套产品流程。兼容旧客户端的输出应由同一源生成，并有差异检查；客户端不支持必要能力时准确报告支持边界。

## 3. 目标技能组织

| 技能职责 | 何时加载 | 必须产生什么 |
| --- | --- | --- |
| 统一交付入口 | 新建、恢复、更新或重审任务 | 范围、下一切片、依赖、结果状态 |
| 产品与工作流理解 | 能力、参与者和流程未清晰 | 产品规则、组合关系、正常与异常流程 |
| 体验恢复与设计 | 存在用户可见交互 | 信息架构、视图、组件状态、视觉和交互规则 |
| 接口、数据与逻辑设计 | 外部契约或必要技术设计不闭合 | 格式、状态、所有权、协作和系统约束 |
| 规格组织与交接 | 内容具备可消费候选 | 多格式产物、公开投影与包内引用 |
| 质量与针对性复核 | 局部设计、整合或交付门 | 具体缺口、可复核判断和下一动作 |

这些是职责，不要求一对一变成上述数量的技能。某类技能独立加载确实能减少上下文或改善效果时再拆分；所有技能共享一套范围和完成语义。

## 4. 技能正文合同

每个技能声明目的与激活条件、输入和读取前提、需要推进的交付、允许改变的状态、必需输出、完成条件、异常与交接。入口正文保持简短；专业方法、模板和检查规则按需引用。

不将整套目标架构复制进每个 `SKILL.md`。引用文件位于可安装包允许的范围内；发布验证必须检查引用有效。`AGENTS.md` 是贡献者在本仓库工作时的规则，不自动成为对任意目标仓库的执行授权。

## 5. 宿主能力合同

宿主接入至少说明文件读取与搜索、允许的执行和写入、上下文与输出限制、取消、错误报告、权限提示、持久化位置和可用外部连接。并不要求宿主支持所有增强操作；功能缺失按能力合同处理。

运行状态留在可写的任务或宿主数据区域，不写入安装包。客户端扩展路径、技能引用和适用 MCP 配置需通过声明规范的校验；标准格式校验与客户端真实加载分别留证。

## 6. 生命周期与兼容

安装或更新时检查清单与版本；首次执行探测必要能力；任务中按需调用；取消时保存一致状态；卸载或升级遵守宿主数据策略。不能静默安装全局依赖、编辑客户端配置或启动未批准服务。

当前的目标宿主包括 Codex、Claude Code 等，但本包不声称已经加载成功。适配矩阵必须记录宿主版本、插件格式版本、实际测试路径、限制与日期；不能从“遵循标准”推导“所有客户端兼容”。

## 7. 借鉴 reverse-skill 的边界

借鉴契约驱动、短入口、可恢复状态、按能力用工具和失败回归；不复制其安全领域对象链、复杂 PRIMARY 路由、工具安装体系或外部仓库委派方式。参考研究是已有历史快照，不作为对方当前实现的重新认证。

当客户端或操作系统需要差异实现时，先共享领域合同，再用兼容测试约束差异。是否采用单一可移植辅助运行实现，应以恢复、安装与维护成本实验决定，不预先复制多套核心业务逻辑。
