# 原生能力与可选 Provider

> 基线：DB-20260928 · 状态：已采纳 · 类型：目标设计
> 本文承接现有愿景，不表示能力已经实现；变更与采纳规则见文档入口。


## 1. 核心分离

工具能力描述要完成什么操作；Provider 描述由谁完成。GitNexus、CodeStory、Serena、OpenDesign 等名称不是产品子系统，也不是安装前提。原生路径使用宿主已经具备且被允许的读、搜、命令、测试和运行能力。

“外部增强可选”不等于“不需要目标产品必要环境”。真实服务、专用数据、商业应用或运行权限若决定待恢复行为，其缺失可能构成交付阻塞。不能承诺原生搜索能替代一切真实观察。

## 2. 能力族与原生路径

| 能力族 | 工作目标 | 原生路径与限制 | 可选增强 |
| --- | --- | --- | --- |
| 文件与文本 | 找到入口、配置和材料 | 宿主读取与搜索；受权限、编码和结果截断限制 | 高效检索与内容索引 |
| 符号与关系 | 找调用、引用、实现与数据流 | 根据源码、导入、测试定向追踪；不能把文本匹配称为完备语义解析 | 语言服务、符号索引、关系图 |
| 版本与变更 | 固定输入并识别影响 | 可用 Git 与文件内容摘要；缺历史则明确限制 | 变更影响分析 |
| 运行与测试 | 观察真实状态和副作用 | 用户允许的构建、测试、命令和服务 | 跟踪、录制、专用运行观察 |
| 体验与视觉 | 恢复完整界面和交互 | 可用浏览器、截图、样式和交互观察；无法运行时不得虚构动态体验 | 设计提取与视觉分析 |
| 数据与协议 | 理解结构、迁移和交换语义 | 配置、Schema、测试及被授权的查询 | 数据库检查、协议录制 |

能力键可以细分，但不预设必须实现统一 SQL、图查询或符号服务 API。能力合同以结果语义为主，Provider 特有操作留在适配层。

## 3. 请求与结果合同

请求至少有：操作目标、范围版本、材料快照、查询或参数、允许副作用、结果预算、超时或取消要求、执行位置和数据外发约束。

结果至少有：操作与请求标识、提供者和版本、实际执行范围、数据与引用、是否截断、是否完整响应、观察条件、限制、失败类型。`success` 只表示操作成功，不意味着目标问题已充分解答。

失败类型区分 `unavailable`、`permission_denied`、`unsupported`、`stale`、`timeout`、`cancelled`、`partial`、`execution_error`。空结果必须说明是“在声明范围内未找到”还是“未能完成搜索”。

## 4. 发现与选择

发现、已配置、可访问、已获授权和实际调用成功是不同状态。MCP 客户端注册存在不代表服务健康；可执行文件存在不代表目标操作可运行。探测应低副作用、可取消，避免每次全量启动工具链。

选择依据包括：当前问题的匹配度、版本新鲜度、授权与数据边界、已观察可靠性、预计成本和延迟。不要默认对同一问题调用全部 Provider，也不根据品牌固定全局顺序。

## 5. 降级与结果标准化

可选增强不可用时，编排重新选择能够解答同一交付问题的原生调查方法。标准化只统一字段和引用，不抹去工具限制，也不能把近似关系变成已验证事实。

例如图索引指出一个调用路径，Agent 仍需检查当前源码或运行条件；索引版本落后时不能作为当前事实。原生路径若不能取得同等信息，应产生明确缺口，而不是填充一个“成功”的空结果。

Provider 没有修改范围、接受设计或宣布最终交付的权限。其输出是材料，进入正常理解和审阅流程。

## 6. 生命周期与扩展

登记能力 → 探测 → 判断授权 → 调用 → 校验响应与来源 → 使用或降级 → 失效缓存。安装、启动服务和修改客户端配置另行授权，不混入普通查询。

新增 Provider 必须提供：能力说明、前置条件、数据边界、失败行为、版本与新鲜度策略、最小测试样例，以及去掉该 Provider 后仍可工作的目标范围验证。没有具体质量或成本收益证据时，不把集成数量当路线图进展。

## 7. 一致性测试

用同一任务和固定输入比较原生模式与增强模式。要求目标范围和最终规范义务不变，允许调查顺序和成本不同；结果差异需追溯到新发现或已证明限制。不得要求两个模型运行逐字一致。

故障注入覆盖：未安装、未注册、无权限、超时、截断、过时索引、不合法路径和资料外发被拒绝。两种模式都不能把缺少必要产品输入的问题假装解决。
