## 3. 本次补齐的设计层

目标架构定义六个逻辑职责区；领域模型区分产品能力与工具能力、事实恢复与独立设计；执行协议定义交错推进、暂停、恢复和重开；状态模型覆盖版本、内部依据和增量失效；套件模型覆盖多格式、公开投影与实施自由；质量模型区分结构、语义、隔离消费和结果验证。

路线图建立 20 项目标能力、7 个里程碑、20 项验收方法和依赖关系，并拆为可执行工作包。它们是完整愿景的建设路径，不是 MVP 功能清单。全部目标能力仍标记为待实现/未验证；本次文档产出不自动提升产品成熟度。

新增的架构决策记录解释为什么采取这条路线；工程待决项给出推荐方向、所需实验和最晚决策点。没有静默选择产品运行语言、正式公开 Schema 或声明宿主兼容。

## 4. 可执行固化的实际范围

新增的设计检查器验证引用、依赖、状态证据和文件边界，并带负向自检；现有基础 CI 保留。它只为设计仓库的一致性提供有限自动保护，不证明自然语言设计充分、不生成产品，也不证明独立重建已经成功。

## 5. 采纳建议

将本包作为一次设计基线 PR 评审，先关注：交付边界是否保持、联合设计是否完整、内部/公开分离是否正确、阶段出口是否可验。文件可作为提案进入仓库，接受具体设计时再更新状态和评审依据。

接受后按 WP01—WP12 推进真实实现与验证；不要因文档齐全直接创建一个“已完成架构”的发布。新的事实允许修订本方案，但变更须显式回到对应架构、合同和 ADR。

本次提供文件与补丁，不对远程仓库推送、创建 PR、自动合并或修改管理设置。
