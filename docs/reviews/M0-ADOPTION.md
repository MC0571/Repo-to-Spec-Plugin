# M0 设计基线采纳记录

> 决定：采纳 M0 目标设计基线；产品能力的实现、验收与回归状态不随之提升。

## 维护者决定与范围

维护者依据 `VISION.md`、设计包、两轮文档审查及下面的 CLI/UI 设计走查，采纳目标产品边界、S1—S6 逻辑职责、核心领域对象、联合设计流程、内部/公开隔离、`SYSTEM_SPEC/` 语义角色、原生与可选 Provider 边界，以及四层评价方式。M0 是对“要建什么、怎样评价”的决定；不是安装、生成、独立消费或重建能力已经可运行的证明。

采纳的设计文件和合同以各文件状态为准。`SYSTEM-SPEC.md` 的候选字段不构成稳定公开 Schema；`STATE-AND-PROVENANCE.md` 的任务级文件与检查点指针仍是 OD02 的实验方案。能力 C01—C20 的详细设计继续标记 `proposed`，四条能力成熟度轴不因本记录自动变化。工作包和开放工程选择仍可按真实证据调整。

## CLI 与 UI 设计走查

以下为**虚构压力场景**，用于检查设计能否承载问题及拒绝不完整交付，不是对真实参考仓库的发现，也不是 Axx 产品验收。

- CLI：以“读取输入、按配置转换并写文件”为场景，逐项检查帮助与非法配置的组合、配置优先级、退出码和 stdout/stderr、已存在目标文件、写入中断、重复执行及恢复。现有 `DeliveryScope`、`DesignElement`、`CoverageObligation` 和 D-02/D-03/Q-02/Q-04 可要求说明具体条件、输出与副作用；“遵循常见优先级”“失败时报错”或只写“原子写入”均不能关闭切片。实际优先级、码值和文件状态必须由 WP02 的固定样例与观察提供。
- UI：以“进入导入任务、观察运行、取消或重试、重连后查询结果”为场景，检查正常/空/加载/错误/部分成功、键盘焦点、响应式、权限以及取消与完成竞争。领域对象、执行协议、规格元素和 D-04/Q-01/Q-05 足以要求 UI 与持久状态一致；只有成功截图、焦点丢失、把断线推断成失败、或本地取消覆盖已完成终态，均不能通过语义与交接门。`docs/examples/DELIVERY-SLICE.md` 明确缺少体验数值及部分失败规则，保留为未闭合反例，不作为完整正例。

这两项走查确认设计有可执行的调查与拒绝路径。WP02 仍须建立真实 CLI、UI、服务、选择性吸收和输入缺失样例，并验证隔离消费方法；WP03 才开始运行骨架实验。B-CLI、B-WEB 与 Axx 均维持未运行。

## ADR 处理与开放决定

| ADR | 采纳范围 |
| --- | --- |
| 0001、0002 | 完整逻辑技术设计与原实现解耦；按交付切片交错理解和设计，共享规则持续整合。 |
| 0003、0004 | 内部依据与公开交接分离；原生操作可用，外部增强可选，缺必要输入不能假装成功。 |
| 0005 | 采纳单一权威、修订冲突、一致恢复及可替换存储语义；任务级文件和检查点指针仅为 OD02 优先实验方案。 |
| 0006、0007、0008 | 每次交付门与代表性结果评测分离；稳定语义角色而非统一固定目录；可移植分发与薄宿主适配，均不等于已发布 Schema 或已验证宿主。 |

OD01/OD02 在 M1 前通过实验决定运行与状态机制；OD03 在 M1 建格式候选、M4 前接受；OD04 对首宿主在 M1 实测，对第二宿主到 M5；OD05 在 WP02 验证隔离办法、首批切片开始小范围消费检查、M4 完成整包检查；OD06 在 M2 前取得初始基线，并在正式对照评测前固定适用指标、方法及通过条件；OD07 在任务接入和发布前处理必要资产与输入；OD08 在受影响切片关闭前处理参考冲突。没有证据支持现在锁定这些工程选择或虚构阈值。

## 证据边界与后续

设计登记、链接和 CI 检查仅证明结构一致。CLI/UI 走查使用构造场景，没有运行生成器、独立消费或产品符合性测试。全部 Cxx 的 `implementation_status=not_implemented`、`verification_status=not_run`、`regression_status=not_established`；M1—M6 仍为 `planned`。M0 的采纳与走查记录是本文件，后续真实失败须回到相应权威文档、合同、ADR 与回归案例修订。
