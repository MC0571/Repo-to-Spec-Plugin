# SYSTEM_SPEC/ 可改写提纲

这份提纲只提示问题，不是固定文件树。删除真正不适用的部分并说明原因；缺材料的部分写为未决，不得删掉伪装完成。大产品可按能力拆分，保持共享规则单一权威。

## 阅读入口

- 产品/能力目标、参与者、声明范围、支持环境与版本、排除项。
- 文件导航、术语、规范性权威与外部标准/运行依赖。
- 若选择性吸收：每项必要依赖的纳入、目标环境契约或获准改造，以及验收。

## 产品与流程

- 每个能力：目标与入口、角色与权限、前置条件、输入/默认/验证、正常步骤与可观察结果。
- 错误、边界、中断、重复、恢复及能力组合；共享规则集中定义。

## 体验与界面（按产品适用）

- 用户旅程、信息架构、页面或命令交互、视图状态、文案与反馈、视觉约束、键盘与无障碍。
- 状态变化怎样同步到界面，等待、失败、恢复时看见什么。

## 数据、接口与逻辑设计

- 数据含义、身份、所有权、生命周期、不变量、状态转换与持久化。
- 外部接口、事件、配置、文件格式、错误、权限与兼容。
- 必要职责与协作、并发/幂等/事务、失败恢复、安全和运行约束。
- 实现自由：可变选择、不可变结果与验证边界。

## 验收

- 场景编号、前置状态与输入、动作、可观察结果、错误及容差。
- 适用的样例数据或测试向量；与正文的规则相互对应。
