# 场景指导：从用户请求选择调查入口

本文件帮助选择调查起点和需要加载的方法，不增加新的执行阶段。一个请求可能同时符合多个场景；从最能决定产品范围的场景开始，再按缺口切换专项方法。专项方法的调查步骤、证据规则和完成标准以对应引用文件为准。

## 共用判定

- 足以开始调查的输入是可定位的参考仓库或版本，以及用户希望保留的结果或明确的目标范围。目标平台、角色、调用方或目标环境若未知，先调查不依赖它们的部分；只有当未知项会改变产品结果、范围或外部契约时才提问。
- 从用户入口、公开消费方式和可观察结果找场景，不以源码目录或某个工具的可用性定义场景。场景指导中的“首入口”是调查材料的起点，不代表功能本身的正式产品入口。
- 依场景加载对应方法与 [工具指南](tools.md)，把结论写进正式 `SYSTEM_SPEC/` 所需的旅程、规则、状态、接口、依赖或验收。源码定位和调查过程留在套件外。
- 运行环境、权限、账号、服务或视觉材料不足时，继续使用文档、调用方、源码、测试、样例和可安全运行的替代路径；注明哪些结论仅由静态证据支持、哪些分支未验证。工具不可用不等于产品行为不存在，也不自动缩小声明范围。

## 完整产品

- **典型请求：**“按当前产品完整重建”“覆盖网站、命令行和 API 的全部用户能力”。**不适用：**仅要仓库摘要、源码导览，或用户只选了一项能力；这两类请求分别不属于产品规格交付或应转到“选择性吸收”。
- **输入与首入口：**确认产品版本、完整范围和目标环境；从 README、安装/使用说明、应用主导航及公开 CLI/API 入口列出用户可达的产品面。范围已明确即可开始列入口；版本或支持环境缺失时标注条件，只在其影响行为和验收时追问。
- **调查与输出：**先用[调查方法](investigation.md)建立边界，再用[能力发现与边界](capabilities.md)逐个整理用户结果。每个结果边调查边写；有界面时加载[体验与视觉恢复](experience.md)，存在失败/中断时加载[行为与异常恢复](behavior.md)，有状态、配置或外部接口时加载[数据、接口与必要技术约束](contracts.md)。输出按产品能力组织的 `SYSTEM_SPEC/`，并由[输出标准](specification.md)定载体；工具选择见 [工具指南](tools.md)。
- **易漏与停止：**容易漏掉跨能力共享的身份、默认值、设置、权限、错误恢复和能力组合；测试/管理入口也要判断是否服务用户结果。只有每个声明结果都能从入口走到结果、边界有纳入/依赖/排除决定且重要设计可验收，才停止全产品枚举。若“完整”所指产品版本或支持环境不同会改变结果，向用户问清；缺运行环境时用用户文档、公开入口、测试和静态路径逐项补证，并把未观察到的体验分支列为未验证。

## UI 完整流程

- **典型请求：**“完整还原注册到设置的页面和操作流程”“规格要覆盖 UI 状态、视觉和键盘操作”。**不适用：**只有 CLI/API 或库调用、且实际产品没有图形界面；此时写清不适用理由并描述真实的人机反馈，不虚构页面。
- **输入与首入口：**需要目标用户/角色和要完成的任务；支持设备/视口、账号或可运行环境可帮助验证，缺少时仍可从已有截图、设计资源和测试开始。首入口是该任务的产品导航或直接操作入口，随后追踪到结果与返回/恢复路径，不从组件目录开始。
- **调查与输出：**以[体验与视觉恢复](experience.md)为主，沿正常任务逐屏核对，再遇到异步等待、取消、失败或数据变化时转到[行为与异常恢复](behavior.md)和[数据、接口与必要技术约束](contracts.md)。工具观察方法见 [工具指南](tools.md)。输出为用户旅程、视图状态、视觉/响应约束、交互反馈、键盘/焦点和与底层状态对应的验收。
- **易漏与停止：**检查空、加载、校验失败、无权限、部分成功、超时/结果未知、离开页面、返回、窄屏和键盘路径；只见截图不能证明交互。旅程中每个关键动作都有前置、反馈、终态和失败恢复，且界面状态与数据状态一致后可停止。角色、平台或关键交互分支会改变结果时提问。不能启动 UI 时比对截图、路由/组件状态、样式令牌、交互测试和文案；明确布局可确认到哪个视口，动态、焦点和辅助技术行为仍未验证。

## CLI、API 与配置

- **典型请求：**“重做这套命令行工具/API 并保持调用兼容”“吸收配置系统和自动化接口”。**不适用：**用户只要求画面/交互复刻且没有外部命令、接口或配置面；有 GUI 的完整产品请求仍需把这些接口作为产品一部分检查。
- **输入与首入口：**确认请求涉及哪些公开调用方式、预期兼容对象及目标运行环境；从 CLI help/示例、API 路由或注册点、配置样例及真实消费者开始。服务账号、凭证或真实调用环境缺失时，仍可从离线消费者和接口样本着手。
- **调查与输出：**以[数据、接口与必要技术约束](contracts.md)为主，按[工具指南](tools.md)第 1、2、5 节追入口、消费者、配置和兼容；对错误、重试、并发转入[行为与异常恢复](behavior.md)，对库/框架等候选要求转入[实现解耦](decoupling.md)。输出为命令/API/配置/文件/事件契约及正反向验收，而不是页面规范。
- **易漏与停止：**命令的 stdout/stderr/退出码、参数默认、工作目录、配置优先级/生效时机、鉴权、版本兼容和部分结果都可能是契约。每个声明入口的合法、非法、权限、重复/冲突和错误结果均可判定后停止；若兼容承诺或目标平台不明且会影响消费者，提问。无法访问真实服务时，用调用方、公开样例、Schema、替身或受控本地测试交叉核对，并将线上权限/一致性留为未验证。

## 导入、导出、批量与异步任务

- **典型请求：**“覆盖批量导入并处理部分无效项”“重做异步导出，含进度、取消、重试和下载”。本场景可叠加于完整产品、UI 或 API 调查。**不适用：**单项、同步且无聚合结果的操作；仍按其主场景调查，不额外套用批量流程。
- **输入与首入口：**至少要知道用户提交什么、预期处理范围和请求保留的批量/异步结果；样例文件、任务入口及结果消费者能显著加快核对。先从上传/命令/API 入口追到后台处理和用户收到最终结果的位置；无法判断导入会修改哪些数据时，继续查样例和写入调用，不先猜策略。
- **调查与输出：**先用[行为与异常恢复](behavior.md)定义单项与整批状态，再用[数据、接口与必要技术约束](contracts.md)追任务、文件、聚合与重试契约；经 UI 呈现时同时用[体验与视觉恢复](experience.md)。批量核对方法见 [工具指南](tools.md)第 3、5、6 节。输出须能区分单项结果、整批完成状态、部分成功条件、进度/错误反馈和可执行恢复验收。
- **易漏与停止：**空输入、重复项、无效项与合法项混合、处理中断/重启、并发提交、已产生副作用后取消、超时但结果未知、文件/任务过期和聚合误报都可能改变结果。单项和整批各自的成功、失败、取消及恢复语义均明确后停止；部分成功、重试是否会重复写入或保留/删除数据仍影响产品时提问。无真实队列或服务时，用确定性夹具、状态/调用方测试和本地替身核对；将队列恢复、时序或线上一致性未覆盖项标出，不宣称已运行验证。

## 库、SDK 与回调

- **典型请求：**“重做这个 SDK 给现有应用调用”“定义库的公开 API、事件和回调语义”。**不适用：**仅内部包、没有可识别的外部消费者，也不构成用户声明范围；不要把每个内部函数都写成契约。
- **输入与首入口：**确认目标是哪个公开包/API、消费者和必要兼容对象；从公开导出、使用文档、示例及调用方测试开始，沿一次真实调用追到结果和资源释放。目标语言或平台未定时，先恢复语言无关语义；仅当 ABI、包管理/安装或兼容选择改变产品承诺时追问。
- **调查与输出：**用[数据、接口与必要技术约束](contracts.md)定义调用边界，用[行为与异常恢复](behavior.md)补充调用失败、取消和生命周期，并用[实现解耦](decoupling.md)判断语言、框架和库是否必需；工具入口见 [工具指南](tools.md)第 1、5 节。输出为公开输入/返回值、错误、资源所有权、同步/异步和回调/事件的触发与顺序语义及验收。
- **易漏与停止：**回调何时触发、是否可能重复或乱序、调用者如何取消/释放、回调期间重入、异常如何返回、并发调用是否安全，按实际公开行为核对。外部调用者无需阅读源码即可正确使用并处理失败后停止；公开兼容层或回调时序未明且用户要求兼容时提问。不能安装/运行 SDK 时，用公开导出、文档、消费者测试、类型/Schema 和示例静态还原；把未执行的编译、运行兼容性标为未验证。

## 选择性吸收

- **典型请求：**“只把权限审核/导入/搜索能力吸收进现有产品”“借用其插件机制的一部分”。**不适用：**用户要完整重建，改用“完整产品”；只说“挑有用的部分”但没有选定结果时，先从其描述和目标产品入口形成可核对候选范围。
- **输入与首入口：**需要用户要保留的结果、参考版本和目标环境中的接入位置；已有服务、身份、数据、配置或 UI 契约有助于定界。先看所选能力的用户入口，再看目标环境入口/已有提供者；目标实现暂不可访问时，仍可追来源能力并把环境侧契约列为待核实。
- **调查与输出：**首载[选择性吸收与依赖闭合](absorption.md)，再用[能力发现与边界](capabilities.md)界定结果与共享规则；按缺口加载[行为与异常恢复](behavior.md)、[体验与视觉恢复](experience.md)、[数据、接口与必要技术约束](contracts.md)及[实现解耦](decoupling.md)。输出明确哪些规则纳入、由目标环境提供的契约、获准改造/排除项、组合入口和端到端验收。
- **易漏与停止：**检查权限/身份、核心数据与生命周期、默认配置、共享状态、错误呈现/恢复、取消和清理的所有权，以及能力交接前后的副作用。每项依赖均有明确提供者或纳入设计，端到端正常与异常路径闭合后停止。若接入会改变结果、权限、兼容或范围，向用户询问批准；目标环境暂不可查时写清具体待核契约及受影响验收，继续完成不受影响的来源调查，不能把尚未核实的提供者当成已满足。
