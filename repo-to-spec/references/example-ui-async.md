# UI 与异步任务的合成教学例

> **纯教学合成材料，不是对本插件或任何参考仓库的调查结论。** 下文的请求、版本、界面、API 和运行结果都是为了演示而设定。真实任务必须重新核对来源、用户目标与运行条件；不得把本例中的数值和规则移植过去。

本例把同一项月度用量导出，从用户请求一路写到 UI、状态、数据、接口、必要技术约束和验收。它还演示如何把来源文档的声称与当前版本实际行为分开。示例 `CSV` 是面向用户的产品输出；它不代表某个发布门禁已通过。

## 用户请求与范围

> 为当前工作区的管理员提供月度用量 CSV 导出。管理员选择已结算月份后启动生成，等待时能看见状态；服务可用时状态变化在五秒内显示。失败后可重试且不会因为双击或网络重试多生成一份。成功后可下载文件，生成内容取请求受理时已结算的数据。只有当前工作区的授权管理员可以查看选项、创建或查询任务及下载文件。运行中的任务不提供取消；本次只覆盖当前页面，不要求任务历史或离开后恢复。

目标要求还包括：最近 24 个已结束的 UTC 月可选，默认上一个完整月份；文件自任务成功起保留 30 天；这些值固定，不提供租户级配置；键盘可完成操作，异步状态变化可被辅助技术感知。一次不同的明确提交可以另建任务；去重范围是同一请求的重放，不是同工作区和月份的全局去重。

范围包含当前工作区、月份选择、提交、等待、失败恢复、下载与权限检查。它不包括取消运行中的任务、跨工作区汇总、任务历史与页面刷新恢复，或报告之外的发布决策。用户离开页面后不提供任务列表或恢复入口；这些是本例明确的范围排除，不是对其他产品的通用建议。

### 矛盾怎样解决

M2 声称新请求会取消旧任务；M3–M6 只表明当前页面没有取消控件或可见取消请求，**尚不能排除新请求隐式取消旧任务**。转查不同键的服务端路径，M7 观察到首任务继续至成功。再核对版本：M2 是 1.3 版文档，M3–M7 来自 2.4 版。因此 M2 是旧版来源声称，不是当前版规范事实。规格采用当前版行为：页面阻止同一进行中操作的双击；重放同一个请求幂等；不同请求不隐式取消旧任务。

若版本无法核实，或当前行为测试、API 契约和受控运行仍互相冲突，就不能挑一个看起来方便的来源写成定论；应把“新提交是否取消旧任务”标为未决并阻止最终交付受影响的这部分规格。

本例也把四种陈述分开保存：M1 是**目标要求**；M2 是**来源声称**；M3–M7 在其覆盖范围内支持**当前来源行为/契约**；“状态须在五秒内更新”是目标要求，而具体如何达到它属于**实现自由**。来源未实现、未集成或目标检查尚未运行，不会反过来使一份已闭合的设计契约变成未决；那是另一个实现验证结论。

## 最终规格片段

以下规则互相引用，作为同一规范的一部分。此处假定合成材料已闭合所需产品决定。

### 边界与共享规则

**SCOPE-1｜月度用量导出**：当前工作区中的授权管理员选择最近 24 个已结束的 UTC 月之一，生成并下载该工作区的 CSV。月度数据范围以 UTC 日历月计算，任务受理时冻结已结算数据快照。一个完成任务只产出该快照对应的文件。

**R-AUTH｜工作区访问**：页面只暴露当前用户有权访问的工作区；此能力继承当前工作区上下文。服务端对选项、任务创建、任务查询和文件下载分别验证当前用户对该工作区的管理员权限。无权访问的资源 ID 与不存在的资源 ID 对外返回相同结果。切换工作区后，旧工作区的待处理视图请求不得更新新工作区的页面。页面隐藏控件只是导航体验，不替代服务端授权。

### 界面与行为

**R-UI-1｜月份选择**：进入页面时显示最近 24 个已结束 UTC 月；默认选择上一个完整 UTC 月。当前月和范围外月份不可选择。选项读取成功且没有可用月份时显示原因和空状态，不显示可提交的表单；读取失败时显示加载错误和重试动作，不得伪装成空状态。

**R-UI-2｜提交与等待**：有效月份下“生成 CSV”可用。首次提交后立即禁用该按钮和月份控件；仅当服务端接受任务后显示 `排队中` 或 `生成中`。当前 API 不提供进度值，界面不得显示百分比。若接口可用，状态变化在五秒内反映到界面；焦点不被强制移动，变化通过可访问状态区域播报。等待中的页面没有取消动作。

**R-UI-3｜受理与状态查询的网络错误**：若提交请求没有得到可判定的响应，显示 `正在确认受理`，保持月份和原请求键，不提供新建请求动作；按该键查询。查到任务后展示其当前状态；查询返回 `404` 时，用相同键和相同内容重放，以让服务端在授权有效时查重或创建；若授权已失效，该重放仍须被拒且不创建任务。查询超时或服务端错误时继续显示 `正在确认受理` 和查询重试动作。若任务 ID 已知但状态查询失败，显示 `暂时无法更新状态`、最后一次已确认状态及其更新时间；可重试查询。以上错误均不是任务 `failed`，都不得生成新键或丢弃最后已确认状态。

**R-UI-4｜完成、失败与恢复**：`succeeded` 且未过期时显示成功状态和下载动作；下载前仍由服务端鉴权。`failed` 显示可理解的失败反馈，保留已选月份，并提供显式重试。重试创建新的请求键和新任务。`422` 月份错误时保留选择并刷新可用月份；`409` 请求键冲突时说明请求无法确认，不静默换键；**已知任务 ID 的状态或文件接口**返回 `404`/授权失效时，清除当前工作区的任务和下载内容并显示通用不可用反馈。按键查询未知受理的 `404` 按 R-UI-3 处理。状态读取超时或服务端错误使用 R-UI-3 的查询失败路径，不冒充业务失败。

**R-UI-5｜到期**：文件在成功后 30 天内可下载。到期后页面显示文件已过期和重新生成动作；旧任务保持 `succeeded`，但文件接口返回到期错误。重新生成视作新的明确请求和新任务。

**R-VIS-1｜布局与错误视觉**：桌面视口中主内容区居中且最大宽度为 `720px`；基础间距按 `8px` 令牌递增。视口宽度不大于 `600px` 时仍为单栏，月份、主动作、状态/结果按此顺序排列，主动作填满可用宽度。错误反馈使用错误令牌 `#B42318` 并显示文字，不得只靠颜色传达；在两种视口下错误说明紧邻月份选择或对应任务状态。实现可选不同布局技术，但这些内容顺序、层级、最大宽度和颜色语义必须可观察。

### 数据状态与共享不变量

**R-JOB-1｜任务状态**：服务端是任务状态的唯一权威写入者。合法路径是 `queued → running → succeeded` 或 `queued/running → failed`；终态不可返回非终态。`succeeded` 只在完整文件可下载后成立；`failed` 不得暴露部分文件。任务记录至少包含 `jobId`、`workspaceId`、`requestedBy`、`month`、`acceptedAt` 和 `state`；成功任务还包含文件 `expiresAt`。不要求存储采用这些字段名，但语义必须相同。

**R-DATA-1｜快照**：任务在受理时固定工作区、UTC 月份和当时已结算数据快照。文件只包含此快照内该月的数据；受理后的补录不改变已完成文件。报告生成或下载失败不得修改源用量数据。文件在成功后 30 天可获取，到期后不可恢复下载；用户可显式重新生成新任务。

### 接口、配置与必要技术约束

| 接口 | 契约 |
| --- | --- |
| `GET /workspaces/{workspaceId}/usage-report-options` | 经 `R-AUTH` 校验后返回可选 UTC 月份；当前月和超出最近 24 个完整月份的值不返回。成功但无月份时带 `emptyReason`；传输/服务错误与空列表可区分。 |
| `POST /workspaces/{workspaceId}/usage-reports` | 请求体含 `month`（`YYYY-MM`）；请求头含 `Idempotency-Key`。有效请求返回 `202` 和 `jobId/state=queued`。同工作区、同键、同请求体的重放返回同一任务；同键不同请求体返回 `409` 且不创建任务。任务活跃期间保留键映射，终态后至少 30 天。非法或范围外月份返回 `422`；未授权按 `R-AUTH` 返回。 |
| `GET /workspaces/{workspaceId}/usage-report-requests/{key}` | 用于受理响应不明时查找原请求。存在则返回原任务 ID 和状态；未知键或按 `R-AUTH` 无权访问均返回相同的 `404`。查询也执行 `R-AUTH`。 |
| `GET /workspaces/{workspaceId}/usage-reports/{jobId}` | 返回任务的权威状态、月份及到期时间；无权和不存在按 `R-AUTH` 处理。传输失败不代表任务失败。 |
| `GET /workspaces/{workspaceId}/usage-reports/{jobId}/file` | 仅对成功且未过期任务返回完整 CSV；失败、过期、无权或不存在均不能返回部分或越权文件。 |

**R-CONFIG-1｜配置与默认**：此能力没有租户可调的时区、月份范围或保留期设置。UTC、最近 24 个已结束月份和成功后 30 天保留期均为本规格的产品规则；不得从运行环境时区或未声明环境变量覆盖。

**R-API-1｜幂等记录期限**：同一请求键在任务排队或运行期间始终映射到原任务；任务进入终态后，该映射至少保留 30 天。客户端只对尚未确认受理的同一操作自动重放原键；终态后的用户显式重试使用新键。

**R-TECH-1｜实现约束**：任务创建必须在服务端原子地绑定幂等键、工作区、月份和快照；并发重放同一键时只能得到同一任务。文件先私下生成，完整成功后才对授权下载者可见；服务端每次访问都执行 `R-AUTH`。队列、数据库、文件存储、前端框架与状态刷新机制可由实现者选择。

**实现自由**：实现可以选轮询或服务端推送、不同队列/存储和内部任务模型；都须保持同请求幂等、状态在 API 可用时五秒内更新、终态语义、快照、权限、失败不暴露部分文件和 30 天可下载期限。若轮询不能满足五秒界面更新约束，实现者需选择其他机制，不能放宽用户可见要求。

| AT-10 | 任务处于 `queued` 或 `running` 时检查页面；再以不同请求键创建第二个任务 | 页面不提供取消动作；第二次创建不隐式取消首任务，首任务可按 `R-JOB-1` 到达终态。 |

| AT-13 | 分别使月份选项请求成功返回空列表和返回网络/服务错误 | 空列表显示 `emptyReason` 和空状态；请求失败显示加载错误与重试动作；两者不混淆，均不显示可提交表单。 |

## 容易写错

- “点击生成后显示进度，失败可重试，成功可下载。”没有定义任务状态、重复提交、受理响应丢失、失败副作用、数据快照、授权或到期语义。
- “按管理员指南，第二次提交取消第一次。”把旧版本来源声称写成当前行为，且没有取消接口、状态转换或验收支撑。
- “使用 React 组件、Redis 队列和 PostgreSQL 表 `usage_reports`。”把一种实现机制冒充规范；这些选择不改变上述契约时应留给实现者。
- “报告生成成功即可继续发布。”将用户数据产物误当成发布门禁。若下游确实要把报告用于门禁，必须另行给出门禁主体、判定规则、失败路径和验收。
- “页面符合当前源码；其他状态由实现者决定。”要求下游回查来源，并把重要产品决定误称实现自由。

即使本例各规则与验收已经闭合，也只能说明这份**合成规格文本**足以表达该范围。它不表示目标系统已经实现、集成、通过检查，或任何真实来源已被验证。
